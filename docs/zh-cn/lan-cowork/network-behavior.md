# LAN Cowork 的网络行为（LAN 上发生了什么）

> 适用于：v4.538.0 及更高版本的 Rust 独立版（`yu-server`）。关于 Python 后端混合配置，
> 请参阅末尾的"与 Python 版本的区别"。

本页面汇总了 **"启用 LAN Cowork 后，你的机器在网络上会开始做什么"** 的内容。
在更改设置之前，请阅读此页面。

---

## 要点

- **默认情况下不做任何事。** Rust 独立版在没有通过下述设置显式启用的情况下，
  不会在 LAN 上进行监听或宣告。
- 启用后，**会被同一 LAN 上的其他节点发现**。这是设计预期的行为。
- **PIN 的有无不会阻止发现的宣告。** 详见"PIN 的关系（容易引起误解的地方）"。

---

## 启用后会开始的操作

| 操作 | 内容 |
|---|---|
| **UDP 监听** | 绑定到 `0.0.0.0:19850`（所有接口） |
| **定期宣告** | 每 10 秒将签名的 HELLO 广播到 `255.255.255.255:19850`。内容包含本节点的 ID、公开密钥、API 端口、主机名等 |
| **其他节点的注册** | 验证接收到的 HELLO 的签名，并将对方节点记录到自己的对等体列表（TOFU） |
| **入站 HTTP 接受** | 下表的对等体端点开始返回响应 |
| **本地分发** | 将接受的对等体事件流向已登录的屏幕订阅的 SSE（`/api/events/stream`） |
| **过期清理** | 每 60 秒清理内存中过期的配对请求和纯文本 PIN |

### 入站接受的端点

| 端点 | 认证 |
|---|---|
| `GET /ext/lan_cowork/api/peer/discover` | **无需会话**（对等体列表查询） |
| `GET /ext/lan_cowork/api/peer/status` | **无需会话**（本节点的描述符） |
| `POST /ext/lan_cowork/api/peer/register` | **无需会话**（对等体自注册。注册目标由服务器端验证） |
| `POST /ext/lan_cowork/api/peer/pair/request` / `pair/verify` | **无需会话**（配对启动。未配对的对方无法拥有会话） |
| `POST /ext/lan_cowork/api/peer/token/renew` | 签名 + nonce（无需 Bearer） |
| `POST /ext/lan_cowork/api/peer/event` / `heartbeat` | 签名 + Bearer 令牌 |

"无需会话"**不是指没有认证**，而是**不要求登录会话**。
未配对的对方无法拥有会话，因此这 5 条路由是例外情况下才开放的。
其他路由如往常一样需要登录。

## 启用和禁用的方法

通过 `config.json` 的 **`extensions` 部分**进行切换。

```json
{
  "extensions": {
    "builtin-lan-cowork": {
      "enabled": true
    }
  }
}
```

- **如果没有该键，则为"禁用"**（Rust 独立版）。
- 需要**重启**才能生效。
- 如果要临时切换，也可以通过启动选项指定。优先级为
  **命令行 > `config.json` > 环境变量 > 默认值**。

| 方法 | 启用 | 禁用 |
|---|---|---|
| 命令行 | `--native-daemon` | `--no-native-daemon` |
| 环境变量 | `YU_LAN_COWORK_NATIVE_DAEMON=1` | 同 `=0` |

> 环境变量仅将 `1` / `true` / `yes` 解释为"启用"。`on` 或 `Y` 将**被视为禁用**。

### 检查是否已启用

```bash
curl -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5000/ext/lan_cowork/api/peer/status
```

| 响应 | 含义 |
|---|---|
| `200` | 启用。对等体功能正在运行 |
| `405` | **禁用**（功能本身未编译） |
| `503` | 启用但未就绪（节点特定密钥未生成，或内部初始化失败） |

> **屏幕上扩展功能列表的显示不可靠。** 扩展功能列表可能会显示 LAN Cowork "启用"，
> 但这是基于同梱信息的显示，**与上述守护进程是否实际运行无关**。
> 判断应基于上述端点的响应或启动日志中的 `native_daemon=...` 行。

## PIN 的关系（容易引起误解的地方）

**认为未设置 PIN 就无法从 LAN 访问任何内容，这种理解是不准确的。**

- **正确的**：使用 `--lan`（在所有接口上监听）需要 PIN，没有 PIN 会导致启动停止。
  默认监听是 `127.0.0.1`，因此**正常启动时 HTTP 面无法从 LAN 访问**。
- **注意 1**：如果直接在 `--host` 中指定 LAN IP，此 PIN 必需检查将被跳过。
  此外，未设置 PIN 时登录门户本身也会打开，因此**避免在无 PIN 的情况下向 LAN 暴露**。
- **注意 2**：**UDP 宣告与是否设置 PIN 无关。** 如果启用，
  即使未设置 PIN 的节点也会每 10 秒向 LAN 广播自己的存在。PIN 只限制 HTTP 面的暴露。

换句话说，**PIN 可以限制 HTTP 面的暴露，但不能阻止发现的宣告。**

### 仅监听回环地址时（v4.539.0 及更高版本）

如果监听地址仅为回环地址（默认值 `127.0.0.1`，桌面版也是如此），
**此节点不会在 LAN 上宣告自身**。即使宣告，其他节点也无法连接。
启动后会记录一次以下警告（这是 WARN 而非 INFO，因此默认可见）。

```
LAN Cowork discovery inactive: server listens on loopback only; bind a LAN address or use --lan
```

如需在 LAN 上使用，请绑定 LAN 地址或使用 `--lan`（`--lan` 需要 PIN）。

> 在 v4.539.0 之前，仅监听回环地址的节点会宣告一个 LAN IP。对等体可以发现它，
> 但无法连接；因此更改了这一行为。

## 启用前需要了解的事项

- **即使禁用，启用期间记录的对等体信息也不会自动删除。** 此外，
  **首次启用并启动时**，会运行旧对等体记录的清理
  （删除距离上次到达后超过 7 天的记录，以及未配对超过 1 小时的记录）。
  建议在切换前备份 `tags.db`。
- 接收到的对等体事件会流向已登录的屏幕订阅的 SSE。**内容源自对方节点的输入**
  （发送者 ID 由服务器端替换为已认证的值）。
- 日志中仅记录**数量、类型和发送者 ID**，不记录事件的内容。
- 如需确认运行状态，请在日志级别启用 INFO
  （例如：`RUST_LOG=yu_server=info`）。在默认设置下，不会输出显示对等体事件接收的行。

## 与 Python 版本的区别

| | Python 后端混合配置 | Rust 独立版 |
|---|---|---|
| 默认值 | **启用**（如果 `config.json` 中没有该项则启用） | **禁用**（需要显式启用） |
| 实现 | Python 扩展负责 | `yu-server` 负责 |

**Rust 独立版故意设置为"默认禁用"。** 这是为了避免仅因更新就改变网络上的行为。
混合配置的行为与以往保持不变。

> 早期文档曾建议使用 `{"lan_cowork": {"enabled": true}}`（最顶层）作为启用设置，
> **但该位置的密钥不会被任何实现读取。** 上述 `extensions` 部分才是正确的位置。
