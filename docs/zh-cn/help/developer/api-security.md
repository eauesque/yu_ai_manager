# API 安全指南

每当添加或更改 API 端点时，请使用此文档。

## 首要决策

每个端点必须提前分类为以下之一：

- `public`
- `session/user`
- `admin`
- `localhost-only`

如果不确定，请选择 `admin`。

## 核心规则

1. 不要假设 `GET` 是安全的。
2. `read-only API keys` 仅用于简单读取。
3. 内部路径、库存、历史记录、内容、日志和分析结果是 `admin`。
4. 本地主机检查必须使用感知代理的辅助程序。
5. 配置端点需要允许列表和严格验证。
6. 秘密必须加密并通过共享辅助程序进行编辑。

## 对于只读密钥不安全

- 内部路径
- 文件/成员 ID 库存
- 提示、注释、转录、聊天日志
- OCR / 分析结果
- 队列、历史记录、审计、批准、调度程序、扫描错误状态
- 扩展 / 配置文件 / 备份 / webhook / 秘密后端状态
- 使用存储的第三方凭证获取的结果

## 本地主机检查

不要直接使用：

```
request.remote_addr == "127.0.0.1"
```

改用现有辅助程序：

- `get_client_ip()`
- `is_local_request()`
- `is_loopback_request()`

## 配置端点规则

必需：

- 密钥允许列表
- 严格的类型验证
- 范围 / 枚举 / URL 验证
- 读取时的秘密编辑
- 秘密的加密存储

禁止：

- 盲 `config.update(...)`
- 请求布尔的 `bool(value)`
- 绕过秘密处理的通用合并

## 秘密

- 永远不要返回当前秘密值
- 永远不要在列表端点中包含令牌/标头/秘密 blob
- 永远不要用掩码占位符覆盖现有秘密
- 始终使用专用存储或共享辅助程序

## 来自 API 的出站请求

不要从 `GET` 端点进行上游探针或发现提取。

如果不可避免：

- 需要 `admin`
- 保持超时短
- 阻止本地主机 / 专用 IP / 元数据目标

## 最少测试

对于敏感端点，添加：

1. `read-only key -> 403`
2. `admin key -> 200`
3. `invalid input -> 400`
4. 秘密编辑检查
5. 感知代理的本地主机回归测试（如相关）

## 审查清单

- 这个 `GET` 真的对公共/只读访问安全吗?
- 它是否暴露了路径、库存、提示、转录、历史记录或原始元数据?
- 它是否泄露了秘密?
- 它是否使用了感知代理的辅助程序?
- 它是否避免了隐式布尔强制?
- 它是否避免了盲配置合并?
- 它是否避免了无意的出站请求?
- 它是否包含了管理员范围的回归测试?

默认策略：从狭窄开始，然后仅在需要时故意打开。
