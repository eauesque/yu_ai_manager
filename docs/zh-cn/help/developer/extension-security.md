# Extension 安全模型

本软件的特色是「任何人都能用 AI 创建 Extension」。
同时，内置了保护你的系统免受恶意 Extension 侵害的机制。

本页说明这些机制的运作方式。
即使你不是技术人员也能看懂。

---

## 基本原则

Extension 在一个**受保护的世界**中运行。

在这个受保护的世界里，Extension 可以相当自由地运作。
添加页面、显示数据、处理图像——这些都是 Extension 的工作。

但是，受保护的世界**之外**的东西——系统核心（core）、其他 Extension、你电脑上的所有文件——它碰不到。
这不是「规则禁止」，而是**在结构上根本碰不到**。

---

## 权限机制

Extension 做任何事都需要**权限**。

权限的设计与智能手机的 App 权限模型完全相同。

- 相机 App 请求使用相机——理所当然
- 相机 App 请求访问你的通讯录——很不正常

Extension 也一样。如果一个加水印的 Extension 请求网络访问权限，你就该起疑。

### 审批流程

1. 安装 Extension（或让 AI 帮你创建）
2. YU AI Manager 自动扫描代码，检查它想做什么
3. 显示 Extension 所请求的权限列表
4. **在你批准之前，Extension 不会运行**

认真阅读审批界面上显示的信息。
特别注意那些以红色标示的权限。

### 批准权限之后

Extension 在你批准的权限范围内运行。
未批准的权限，Extension 再怎么努力也用不了。
不是「尝试使用时被拒绝」，而是「根本看不见」。

---

## 三重独立监控

你的 Extension 受到三个独立机制的监控。
这三者互相独立——即使其中一个被骗过，另外两个仍然正常运作。

### 1. 代码扫描

自动分析 Extension 的代码，检测危险模式。
执行外部程序、直接操作数据库、动态执行代码——这些都会被立即检测到。

### 2. 权限控制

Extension 调用 API 时，系统会确认它是否持有有效的「许可证」（Capability Token）。
许可证只有在你批准权限时才会签发。
Extension 自己无法伪造许可证。

### 3. 审计记录

Extension 的所有操作都会被记录。
这些记录保存在 Extension 自身无法篡改的独立位置。

一旦检测到异常——例如，Extension 尝试执行未声明的动作——系统会自动发送通知，必要时吊销 Extension 的许可证。

---

## 用 AI 创建 Extension 的情况

从 Claude Desktop 创建 Extension 时，创建出来的 Extension 会自动以**最严格的限制等级**注册。

这就像不会在新员工第一天就把金库钥匙交给他一样。
先以有限的权限运行，确认没有问题后，再按需追加权限。

### AI 创建的 Extension 能做什么

**无需批准即可使用：**
- 读取和显示数据
- 在 UI 中添加页面
- 添加设置界面

**需要批准：**
- 与外部服务通信
- 写入数据库
- 读取文件

**无论如何都不可能做到：**
- 读取或修改系统核心（core）
- 读取或修改其他 Extension
- 执行外部程序
- 伪造许可证

---

## 定期检查

Extension 不是批准一次就完事了。

如果代码被修改，且修改量超过一定阈值，就会要求**重新批准**。
这是为了防止通过逐步小幅修改，在不知不觉中把 Extension 变成完全不同的东西。

此外，系统会定期自动重新检查代码。
即使批准时没有问题，新的检查规则也可能发现问题。

---

## 你该做的事

1. **好好读权限审批界面** — 搞清楚它在请求什么再批准
2. **拒绝不合理的权限请求** — 图像处理不需要网络访问
3. **不要忽略通知** — 检测到异常时去确认
4. **不要安装来路不明的 Extension** — 这是常识

反过来说，只要做到这些就安全了。
剩下的交给系统来保护你。
