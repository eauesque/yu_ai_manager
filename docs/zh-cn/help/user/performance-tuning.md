# 性能调优指南

本指南适用于管理 10 万个以上文件的环境，帮助您顺畅使用 YU AI Manager。
默认设置已包含许多自动优化，但根据环境调整可进一步改善性能。

---

## 1. 推荐硬件规格

| 项目 | 最低要求 | 推荐（10 万文件以上） |
|------|---------|------------------------|
| CPU | 2 核心 | 4 核心以上（缩略图生成会并行处理） |
| RAM | 4 GB | 8 GB 以上 |
| 存储 | HDD | **强烈推荐使用 SSD** — 直接影响数据库的响应速度 |
| 网络 | — | 通过 LAN 使用时推荐 1 Gbps 以上 |

**特别重要**：数据库文件 (`data/tags.db`) 务必放在 SSD 上。
图片文件本体放在 HDD 上没问题，但 DB 若在 HDD 上，搜索和浏览速度会显著变慢。

---

## 2. 初次扫描的优化

### 分割扫描根目录

一次扫描大量文件会花费较长时间。
建议在 Settings > Scan Roots 中将扫描根目录分成多个进行注册，分阶段扫描。

- 先扫描最常使用的文件夹
- 其余文件夹加入扫描队列（会自动依次处理）
- 重复注册同一文件夹会自动检测并跳过

### 扫描中仍可浏览

扫描中搜索和缩略图显示仍可正常使用。
内部使用只读数据库连接，扫描的写入处理不会阻塞浏览。

### 扫描完成后的自动优化

扫描完成时会自动更新数据库统计信息（ANALYZE）。
借此优化搜索查询的执行计划，后续搜索将更加快速。
无需任何特别操作。

---

## 3. 浏览速度的改善

### Service Worker 缓存

浏览器的 Service Worker 会自动缓存以下内容：

| 种类 | 缓存上限 | 效果 |
|------|-------------|------|
| 缩略图 | 5,000 件 | 第二次以后的网格显示即时 |
| 预览（1200px） | 200 件 | 加速弹窗显示 |
| 原尺寸图片 | 50 件 | 最近浏览过的图片再显示即时 |

Service Worker 由浏览器自动管理，无需特别设置。
若要清除缓存，可在浏览器开发者工具 > Application > Storage 中操作。

### 启用虚拟滚动

显示数千条搜索结果时，启用虚拟滚动可大幅改善渲染性能。

**启用步骤**：Settings > Appearance > 将「Virtual Scroll」设为 ON

虚拟滚动仅将屏幕可见范围的卡片渲染到 DOM，大幅降低内存用量和渲染负担。
数万件规模的图库强烈推荐启用。

### WebP 缩略图

缩略图以 WebP 格式生成（比 JPEG 小 30-40%）。
借此减少传输量，特别在 LAN 访问时效果显著。
无需设置，自动应用。

---

## 4. 搜索性能

### 索引的效果

数据库已自动创建针对主要搜索模式优化的索引。
日期排序、标签筛选、路径搜索等均可高速运行。

**参考指标**：
- 无筛选搜索：28 万件规模下响应在 50ms 以内
- 含标签筛选搜索：100ms 以内
- 路径搜索（FTS5）：50ms 以内

### FTS5 全文搜索 vs LIKE 搜索

路径搜索自动使用 FTS5 (Full-Text Search) 索引。
相较于传统的 LIKE 搜索 (`%keyword%`)，速度快 20-100 倍。

若无法使用 FTS5（从旧版 DB 升级时等），会自动回退至 LIKE 搜索。
执行一次扫描即可构建 FTS5 索引。

**中文搜索注意事项**：包含中文字符的搜索内部可能会使用 LIKE 回退。
这是 SQLite FTS5 分词器的限制，属于正常行为。

## 5. 视频播放的优化

### Faststart 缓存

为加速 MP4/MOV 文件的视频播放，会自动应用 faststart 处理。
已 faststart 处理的视频可立即开始流媒体播放。

| 项目 | 值 |
|------|-----|
| 缓存位置 | `cache/faststart/` |
| 容量上限 | 4 GB（以 LRU 自动管理） |
| 单文件上限 | 500 MB |
| 对象 | MP4, MOV（WebM 不需要，因此跳过） |

**体感改善参考**：

| 文件大小 | 无 faststart | 有 faststart |
|--------------|---------------|---------------|
| 5-50 MB | 等待 2-10 秒 | 约 200ms 开始播放 |
| 50-200 MB | 等待 10-60 秒 | 约 500ms 开始播放 |
| 200-500 MB | 等待数分钟 | 约 1 秒开始播放 |

### 确认 FFmpeg

faststart 处理需要 FFmpeg。若未安装，视频将在完全下载后才开始播放。

```bash
ffmpeg -version
```

若 PATH 中找不到 FFmpeg，请从[官方网站](https://ffmpeg.org/download.html)安装。

## 6. 内存用量管理

### SQLite mmap

大规模数据库（10 万文件以上）会自动将 SQLite 的 mmap（内存映射 I/O）设为 1 GB。
借此让读取查询利用 OS 的页面缓存来加速。

**RAM 4 GB 以下的环境**：mmap 可能会造成内存压力。
此时请监控系统可用内存，若频繁发生交换（swap），请关闭其他应用程序。

### 浏览器标签页管理

YU AI Manager 通过 SSE (Server-Sent Events) 与各标签页进行实时通信。

- 每个 IP 最多 10 个同时 SSE 连接
- 关闭不需要的标签页可释放连接资源
- 打开大量标签页也会增加浏览器的内存用量

**推荐**：同时打开的标签页控制在 3-4 个以内。

## 7. 故障排除 — 感觉「很慢」时的检查清单

### 基本确认

- [ ] **是否使用 SSD**：若 `data/tags.db` 在 HDD 上，所有操作都会变慢
- [ ] **是否已安装 FFmpeg**：视频播放加速的必要条件
- [ ] **浏览器标签页数**：确认是否打开了 5 个以上

### 浏览速度慢

- [ ] **启用虚拟滚动**：Settings > Appearance > Virtual Scroll
- [ ] **不要清除浏览器缓存**：Service Worker 的缓存正在发挥作用
- [ ] **确认是否正在扫描**：扫描中可正常使用，但初次缩略图生成需要时间

### 搜索速度慢

- [ ] **完成扫描**：扫描完成时会执行 ANALYZE，搜索将被优化
- [ ] **搜索结果超过 10 万件**：请添加筛选条件（标签、日期、路径等）以缩小范围

### 视频播放慢

- [ ] **确认 FFmpeg 是否存在**：以 `ffmpeg -version` 确认
- [ ] **faststart 缓存容量**：确认 `cache/faststart/` 文件夹是否超过 4 GB（自动管理但可确认）
- [ ] **文件大小**：超过 500 MB 的视频不在 faststart 缓存范围内。以 Range 传送播放，但首次会稍慢

### 服务器整体负担重

- [ ] **同时访问数**：SSE 连接是否超过每 IP 10 个
- [ ] **上传中**：是否正在发送接近 100 MB 上传上限的文件
- [ ] **Settings > Logs 选项卡**：确认服务器日志中的错误或警告

## 8. 性能指标参考

正常优化环境下的响应时间参考。

| 操作 | 28 万文件规模 | 10 万文件规模 |
|------|-----------------|-----------------|
| 网格显示（首次） | 200-500ms | 100-300ms |
| 网格显示（有缓存） | 50ms 以下 | 50ms 以下 |
| 标签搜索 | 100ms 以下 | 50ms 以下 |
| 路径搜索（FTS5） | 50ms 以下 | 30ms 以下 |
| 缩略图（缓存命中） | 5ms 以下 | 5ms 以下 |
| 视频播放开始（faststart 已处理） | 200ms | 200ms |

若大幅超过这些数值，请确认上述检查清单。

## 高速模式（Rust 服务器）

在受支持的环境中，启动会自动切换到 Rust 服务器（`yu-server`）。

可在设置 ->「服务器」->「高速模式」中选择**获取方式**：

- **下载发布的二进制文件**（默认）-- 不编译
- **在本机编译** -- 不下载
- **先下载，失败则编译**

编译需要 8GB 以上可用磁盘空间，并会大量占用 CPU 和内存。**在内存较小的设备（如 Raspberry Pi）上可能耗尽交换空间并导致整个系统崩溃。** 编译期间所有功能仍可使用。在 Windows 上编译还需要 Visual Studio 的生成工具（链接器）。

进度显示在同一画面上（已用时间、cargo 的最新一行、成功或失败，以及是否中途停止）。原始日志位于 `bin/fast-mode-build.log`。

当高速模式因本副本自身的状态被拒绝时（web 包过旧、存在随附清单之外的扩展等），重新获取二进制文件也无法解决，因此既不下载也不编译。原因同样显示在该画面上。
