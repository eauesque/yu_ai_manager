# 遇到问题时的自助诊断和报告

当 YU AI Manager 无法运行或行为异常时，您可以自行收集原因线索并向开发者报告。本指南汇总了具体步骤。不需要命令行或 Git 知识。

## 1. 首先按"报告问题"

1. 在浏览器中打开应用，从屏幕右上角菜单中选择 **诊断 (Diagnostics)**。
2. 按下 **"报告问题"** 按钮。
3. 稍等片刻后，系统会创建一个 `repair/2026XXXX-HHMMSS/` 文件夹。其中包含以下自动报告集合：
   - 环境信息、最近的日志、设置（个人信息和令牌已掩盖）
   - AI 修复用的提示词模板

按 **"打开文件夹"** 会在资源管理器中打开该文件夹。按 **"制作为 ZIP"** 可将其打包为一个 zip 文件。

> 关于掩盖处理：用户名、邮箱、API 密钥类似的字符串、IP 地址等会自动替换为 `<REDACTED>`。处理不一定完整，所以共享前请检查一遍内容。

## 2. 共享

将 ZIP 文件附加到开发者、支持窗口或 Discord 等。按 **"复制 Discord 用消息"** 按钮可生成一条现成的简短消息，直接粘贴即可。

## 3. 可以自行尝试的临时解决方案

### 3-A. 环境检查 (doctor)

在诊断屏幕上按 **"环境诊断"** 按钮，会以 markdown 格式显示 Python、GPU、DB 等的状态。请依次尝试标记为红色 (ERROR) 或黄色 (WARN) 的项目中列出的 `fix_hint`（修复提示）。

### 3-B. 用 Safe Mode 重新启动

如果正常启动失败、应用崩溃、或一直在加载无法停止，可以用 **Safe Mode** 启动。

- Windows：双击 `start.bat --safe-mode`（或在快捷方式末尾添加 ` --safe-mode`）
- macOS / Linux：从终端运行 `./start.sh --safe-mode`

在 Safe Mode 中，您可以：

- 检查设置
- 使用"报告问题"和"环境诊断"
- 应用开发者提供的 **安全更新包 (update.zip)**（仅替换文件，自动修复脚本无效）

Safe Mode 会持续到下次正常启动。正常重启后会恢复到普通模式。

### 3-C. 应用更新包 (update.zip)

如果收到来自开发者的 `update.zip`：

1. 诊断屏幕 → **"应用更新"** 部分
2. 选择文件，确认 **验证 (Verify)** 显示为绿色
3. 在确认对话框中按 **应用**
4. 按照显示的指示重启

> 验证显示为红色的 zip 千万不要应用。可能是被篡改或者是其他应用的包。

如果出现问题，可以用 **"撤销上次更新 (Rollback)"** 恢复到之前的状态。

## 4. 不要做的事

- 将掩盖前的原始日志贴到 SNS / 公开论坛
- 应用来源不明的 `update.zip`
- 手动修改 `data/` 文件夹或 `tags.db`

## 遇到问题

如果仍未解决，请连同 ZIP 文件一起报告"执行了什么操作，发生了什么情况"。AI 将读取 `prompt_for_codex.md` / `prompt_for_claude.md`，并提出修复补丁方案。
