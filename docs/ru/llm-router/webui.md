# WebUI LLM Router

Панель управления администратора, доступная по адресу `/llm-router`. Позволяет проверять статус зарегистрированных backends и включать/отключать их.

---

## Макет страницы

```
┌─────────────────────────────────────┐
│  🤖 LLM Router          [Refresh All] │
├─────────┬─────────┬────────┬─────────┤
│Backends │ Enabled │ Models │ Aliases │  ← Карточки резюме
├─────────┴─────────┴────────┴─────────┤
│  Таблица Backends                    │
├───────────────────────────────────────┤
│  Таблица Routing Aliases             │
└───────────────────────────────────────┘
```

### Карточки резюме (4)

| Карточка | Содержание |
|---|---|
| **Backends** | Общее количество backends зарегистрированных в каталоге |
| **Enabled** | Количество backends, которые не отключены |
| **Models** | Общее количество моделей, предоставляемых всеми backends |
| **Routing aliases** | Количество aliases, определенных в файле конфигурации |

Значения карточек автоматически отображаются путем выборки `/api/llm_router/status` при загрузке страницы.

## Таблица Backends

Каждая строка соответствует одному физическому backend (например, экземпляр Ollama).

### Описания столбцов

| Столбец | Описание |
|---|---|
| **Alias** | Уникальное короткое имя, идентифицирующее backend (например `ollama-mac`, `mdns-pi5-hailo`). Используется как ключ для конфигурации маршрутизации и разрешения alias |
| **Base URL** | Базовый URL конечной точки совместимой с OpenAI backend (например `http://192.168.1.10:11434`) |
| **Status** | Статус подключения backend. Смотрите подробности ниже |
| **SLO** | Статус нагрузки ресурсов backend (`vision_idle` / `vision_active` / `unknown`). Используется для Hailo Vision backends |
| **Models** | Количество моделей полученных при последнем зондировании. Может быть расширяемым для показа детального списка в зависимости от реализации |
| **Last Seen** | Дата и время последнего успешного ответа (ISO 8601). `null` если ни один успешный ответ не был получен |
| **Actions** | Кнопки действий для каждого backend (смотрите ниже) |

### Значения статуса

| Значение | Значение |
|---|---|
| `ready` | Последнее зондирование было успешным и список моделей был получен |
| `unreachable` | Произошла ошибка timeout соединения |
| `unknown` | Зондирование еще не выполнялось (например, сразу после запуска) |
| `probing` | Зондирование в настоящее время выполняется (может кратко появиться в UI во время Refresh) |

> **Подсказка**: `unreachable` backends исключены из маршрутизации но остаются в каталоге. После восстановления сети выполните Refresh All или отдельный Refresh, чтобы восстановить их в состояние `ready`.

### Значения SLO

| Значение | Значение |
|---|---|
| `vision_idle` | Задача Vision неактивна. Нагрузка LLM низкая |
| `vision_active` | Выполняется задача Vision. LLM router может отдать приоритет другим backends |
| `unknown` | Информация SLO недоступна (non-Hailo backend или получение ошибилось) |

## Кнопка Refresh All

Нажмите **Refresh All** в верхнем правом углу, чтобы принудительно зондировать все backends, обновляя списки моделей и статусы.

- Кнопка отключается во время выполнения и страница перерисовывается при завершении
- Внутреннее поведение: Вызывает `POST /api/llm_router/refresh` (без body) для выполнения `discover_all` для всех backends
- Отдельные refresh может быть доступен через кнопку Refresh в столбце Actions (зависит от реализации)

## Отключение / Включение отдельных backends

### Шаги

1. Посмотрите столбец **Actions** в таблице backends
2. Нажмите кнопку **Disable** в строке backend, который вы хотите отключить
3. Кнопка изменится на **Enable** и строка будет затемнена
4. Для повторного включения нажмите **Enable**

### Поведение и настойчивость

- Изменения немедленно отражаются в каталоге в памяти
- Одновременно выполняется атомарная запись в `data/llm_router_state.json`

  ```json
  {
    "version": 1,
    "disabled_aliases": ["ollama-slow", "mdns-pi5"]
  }
  ```

- Отключенное состояние сохраняется при перезагрузках приложения
- Если backend обнаруженный через mDNS был отключен перед запуском, отключенное состояние автоматически применяется после обнаружения (механизм `_pending_disabled`)
- Если запись ошибилась, состояние в памяти откатывается для избежания несоответствия с диском

### Поведение отключенных backends

- Исключены из маршрутизации в конечных точках совместимых с OpenAI, таких как `/v1/chat/completions`
- Прямая маршрутизация на отключенный backend возвращает `503 Service Unavailable`
- Отключенные backends все еще появляются в таблице WebUI (для видимости статуса и повторного включения)

## Таблица Routing Aliases

Отображает отображение между логическими именами моделей и физическими ID моделей определенными в файле конфигурации.

| Столбец | Описание |
|---|---|
| **Alias** | Логическое имя, которое клиенты указывают в параметре `model` (например `default-llm`, `fast-chat`) |
| **Physical Model** | Физический ID модели, который фактически обрабатывает запрос (формат: `backend-alias/model-name`, например `ollama-mac/qwen2.5:7b`) |

### Роль Aliases

Aliases позволяют переключать backends или модели без изменения кода клиента.

- Клиенты отправляют запросы используя логическое имя, такое как `"model": "default-llm"`
- LLM Router разрешает `default-llm → ollama-mac/qwen2.5:7b` и маршрутизирует запрос
- При миграции backend на другую машину просто измените цель alias

Aliases статически определены в файле конфигурации и WebUI отображает их в режиме только для чтения. Изменения требуют редактирования файла конфигурации и перезагрузки приложения.

## Распространенные операции

### Когда backend недоступен

1. Убедитесь, что сервис backend (Ollama, и т.д.) запущен
2. Выполните **Refresh All** или отдельный Refresh
3. Если проблема сохраняется, проверьте детали ошибки в столбце `last_error` (или ответе API)

### Постоянное отключение backend обнаруженного через mDNS

1. Нажмите **Disable** в столбце Actions целевого backend
2. Alias сохраняется в `data/llm_router_state.json`, поэтому остается отключенным даже после переобнаружения

### Временная остановка нагрузки на определенный backend

Используйте **Disable** чтобы немедленно исключить его из маршрутизации, затем **Enable** чтобы восстановить его по завершении. Перезагрузка не требуется.
