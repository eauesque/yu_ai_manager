# LAN Cowork

> Целевая версия: v4.55.0 и выше (аутентификация PIN доступна с v4.92.0)

## Что такое LAN Cowork?

LAN Cowork - это функция расширения, которая позволяет координировать несколько узлов yu_ai_manager в сети.  
Каждая машина работает независимо, при этом позволяя распределять тяжелую обработку или управлять коллективно как Fleet.

```
┌──────────────┐   Обнаружение mDNS   ┌──────────────┐
│  Windows PC  │◄────────────────────►│   Mac Mini   │
│ (GPU включен)│   Спаривание PIN    │ (Управление) │
│              │◄────────────────────►│              │
│  Распределённые │                  │ Управление   │
│  вычисления  │                      │   Fleet      │
│(tagger и т.д)│                      │              │
└──────────────┘                      └──────────────┘
        ▲                                     ▲
        └─────────────────────────────────────┘
                      ▼
              ┌──────────────┐
              │ Raspberry Pi │
              │ (Hailo NPU)  │
              └──────────────┘
```

## Обзор функций

| Функция | Описание |
|---|---|
| **Автоматическое обнаружение mDNS** | Автоматически обнаруживать узлы в одной LAN без конфигурации |
| **Спаривание PIN** | Аутентификация PIN с одобрением администратора для выдачи токенов между узлами |
| **Распределённые вычисления** | Параллельная обработка tagger, CLIP, YOLO и Whisper на нескольких узлах |
| **Распределение генерации** | Делегирование задач SD WebUI / ComfyUI на узлы LAN |
| **Управление Fleet** | Централизованное управление логами и обновлениями версий на всех узлах |
| **Трансляция событий узлов** | Потоковая передача событий от других узлов в ваш собственный SSE |
| **Маршрутизация LLM** | Автоматическая регистрация обнаруженных узлов в LLM Router |

## Шаги настройки

### 1. Включение

Добавить в `config.json`:

```json
{
  "extensions": {
    "builtin-lan-cowork": {
      "enabled": true,
      "peer_name": "my-desktop"
    }
  }
}
```

> **Примечание**: Эта страница ранее указывала ключ активации на верхнем уровне как `{"lan_cowork": {...}}`, но ни одна реализация не читает ключ в этом месте. Приведённый выше раздел `extensions` — правильное место.

> **Значение по умолчанию зависит от бэкенда:** бэкенд Python (гибридный) считает отсутствующий ключ **включённым**, тогда как автономный сервер Rust остаётся **отключённым**, пока его явно не включат. О том, что происходит в сети после включения, см. [Поведение в сети](network-behavior.md).

После перезагрузки:
- Начать прослушивание других узлов на UDP 19850
- Начать объявление _yu-ai._tcp.local. через mDNS

### 2. Спарить узлы

Для подключения от Узла A к Узлу B:

1. **WebUI Узла A** → `Параметры` → `LAN Cowork` → Добавить URL Узла B
2. Узел A отправляет `POST /api/lan/pair/request`
3. **WebUI Узла B** → `/lan-cowork/peers` → Одобрить во вкладке "Ожидание одобрения"
4. 6-значный PIN отправляется на Узел A (через SSE)
5. Узел A вводит PIN → Получить Bearer-токен (действителен 30 дней)

> **Примечание**: Спаривание является односторонним. Выполните как A→B, так и B→A.

Подробности см. в разделе [Аутентификация PIN между узлами и спаривание токенов](peer-auth.md).

### 3. Проверка операции

```bash
# Список обнаруженных узлов (с Узла A)
curl http://localhost:5000/api/mdns/peers

# Узлы, распознанные LAN Cowork
curl http://localhost:5000/api/lan/peers
```

## Настройка для каждой функции

### Распределённые вычисления

Распределённые вычисления становятся доступны автоматически после завершения спаривания.

- `Параметры` → `LAN Cowork` → Включить типы вычислений (tagger/CLIP/YOLO/Whisper) для каждого узла
- Или настроить индивидуально через матрицу на странице `/mesh-inference`

Подробности: [Настройка распределённых вычислений](../mesh-inference/setup.md)

### Управление Fleet

Настройте узел "главный" для управления другими узлами:

```json
{
  "extensions": {
    "builtin-lan-cowork": {
      "fleet": {
        "chief": true,
        "allow_remote_update": true,
        "allow_update_from": [
          "<paired peer_id>"
        ]
      }
    }
  }
}
```

Подробности: [Управление Fleet](../features/fleet-admin.md)

### Распределение генерации (Делегирование задач SD / ComfyUI)

Автоматически распределять задачи генерации на узлы с GPU. Доступно через регистрацию бэкенда из файла конфигурации или автоматическое обнаружение mDNS.  
Если Узел B работает с SD WebUI / ComfyUI, он станет доступен сразу после настройки.

## Требования к сети

| Порт / Протокол | Назначение | Обязательно |
|---|---|---|
| UDP 5353 | mDNS (обнаружение узлов) | Только одна LAN L2 |
| UDP 19850 | Обнаружение LAN Cowork | Только одна LAN L2 |
| TCP 5000 (по умолчанию) | API, спаривание, вычисления | Между узлами |

- mDNS не работает через маршрутизаторы или VPN (используйте фиксированный IP или имя хоста `.local`)
- Убедитесь, что UDP 5353 и TCP 5000 открыты в LAN в вашем брандмауэре

## Безопасность

- mDNS не имеет аутентификации. **Используйте только в домашних сетях или доверенных сетях**
- В общественных Wi-Fi или общих LAN отключите с помощью `"mdns": {"enabled": false}`
- Связь между узлами защищена Bearer-токенами из спаривания PIN (хранятся как хэш scrypt)
- `ip_check_mode: strict` разрешает только IP, с которого был выдан токен (по умолчанию)
