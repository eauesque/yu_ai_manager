# PIN-аутентификация и сопряжение токенов между пирами

**Версия реализации**: 4.92.0

---

## Обзор

До v4.92 в LAN-коммуникации между пирами идентификация осуществлялась только через заголовок `X-Peer-Id`.
Этот заголовок мог быть подделан любым участником LAN — безопасность была недостаточной.

С v4.92 переход на метод **сопряжения токенов на основе PIN-подтверждения**:

- При первом подключении отправляется «запрос на сопряжение»
- Администратор одобряет его в интерфейсе управления, генерируя 6-значный PIN
- После ввода PIN выдаётся Bearer-токен (действителен 30 дней)
- Последующие соединения аутентифицируются через `Authorization: Bearer <token>`

---

## Процесс сопряжения

```
[Пир-инициатор A]                     [Пир-получатель B]
       |                                      |
       |--- POST /api/lan/pair/request ------->|
       |    (peer_id, display_name, public_key)|
       |                                      |
       |                     Администратор подтверждает в /lan-cowork/peers
       |                                      |
       |<--- SSE: peer_pairing.pin_ready ------|
       |    (6-значный PIN, действителен 5 мин)|
       |                                      |
       |--- POST /api/lan/pair/verify -------->|
       |    (peer_id, pin)                     |
       |                                      |
       |<--- 200 OK: { token, expires_at } ----|
       |    (Bearer-токен, действителен 30 дней)|
       |                                      |
       |--- Далее Authorization: Bearer <token> |
```

---

## Интерфейс управления (`/lan-cowork/peers`)

### Ожидающие запросы

При новом запросе на сопряжение отображается на вкладке «Ожидают подтверждения».

- **Одобрить**: Генерация PIN, уведомление пира-инициатора через SSE
- **Отклонить**: Удалить запрос. Инициатору вернётся 403

### Список подключённых пиров

| Столбец | Содержимое |
|---------|-----------|
| Имя | Отображаемое имя пира |
| IP-адрес | Последний подтверждённый исходящий IP |
| Срок действия | Срок действия Bearer-токена (30 дней) |
| Последнее подключение | Время последнего heartbeat |
| Операция | Кнопка отзыва токена |

## Параметры конфигурации

### `ip_check_mode`

| Значение | Поведение |
|---------|----------|
| `strict` | Только точное совпадение с IP при выдаче токена (по умолч.) |
| `cidr` | Разрешить любой IP в диапазоне CIDR `allowed_cidr` |
| `rfc1918` | Разрешить все приватные IP (192.168.x.x / 10.x.x.x / 172.16-31.x.x) |

### `allow_legacy_auth`

- `true`: Разрешить некоторые операции только с заголовком `X-Peer-Id` (по умолч.: `true`)
- `false`: Отклонять все подключения без Bearer-токена

> **Примечание**: Операции с методом DELETE (остановка сканирования, принудительное удаление и т.д.) всегда требуют Bearer-токен, независимо от `allow_legacy_auth`.

---

## Примечания по безопасности

### Хэширование токенов

Выданные Bearer-токены **не хранятся в открытом виде** в базе данных.
Хранятся в виде хэша scrypt (N=16384, r=8, p=1).

### Маскировка в логах

- Заголовки `Authorization: Bearer <token>` автоматически заменяются на `Bearer [REDACTED]`
- PIN-коды не сохраняются в логах

### Ограничение скорости

| Эндпоинт | Лимит |
|----------|-------|
| `POST /api/lan/pair/request` | 10/мин/IP |
| `POST /api/lan/pair/verify` | 30/мин/IP |

PIN действителен 5 минут и может быть проверен только один раз.

## Устранение неполадок

### Запрос на сопряжение не получен

- Проверить корректность URL партнёра
- Убедиться, что порт открыт в брандмауэре
- Проверить логи партнёра на предмет получения `pair/request`

### Истёк срок действия PIN

Срок действия PIN — 5 минут. Повторно нажмите кнопку «Одобрить» в интерфейсе управления.

### Токен внезапно перестал работать

Возможные причины:
1. Администратор отозвал токен в интерфейсе
2. Истёк срок действия 30 дней
3. При `ip_check_mode: strict` изменился IP-адрес

Выполните повторное сопряжение.
