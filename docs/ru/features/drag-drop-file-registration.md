# Регистрация файлов путём перетягивания

Перетягивайте файлы изображений/видео на главную страницу библиотеки (`/`), чтобы сохранить их
в настроенную директорию **Drop Inbox** и автоматически зарегистрировать их в
библиотеке. Используется обычный путь сканирования (`scan_one`), поэтому извлечение метаданных,
генерация миниатюр и теггирование работают так же, как при обычном сканировании.

## Поведение

1. С открытой главной страницей перетягивайте файлы из файлового проводника или другого браузера
2. На окне появляется оверлей, показывающий целевой путь (Drop Inbox)
3. При отпускании каждый файл копируется в Drop Inbox и регистрируется
4. Уведомление показывает количество успехов и ошибок

## Разрешение Drop Inbox

Drop Inbox разрешается в этом приоритете:

1. `drop_inbox_dir` из `config.json` (явная настройка)
2. Если не установлено: первый включённый корень сканирования используется как есть

**Ограничение**: `drop_inbox_dir` **должна** находиться внутри одной из записей `scan_roots`.
Любой путь вне корней сканирования отклоняется с HTTP 400. Это сохраняет
инвариант, что корни сканирования — единственный источник истины для файлов библиотеки.

## Пример конфигурации

```json
{
  "scan_roots": [
    { "path": "D:/Pictures/AI", "enabled": true, "recursive": true }
  ],
  "drop_inbox_dir": "D:/Pictures/AI/inbox"
}
```

`drop_inbox_dir` создаётся, если она не существует (её родительская директория всё ещё должна
находиться внутри `scan_roots`).

## Обработка столкновения имён

Если файл с тем же именем уже существует в папке входящих, суффиксы `_1`, `_2`,
... автоматически добавляются. Существующие файлы никогда не перезаписываются.

## Разрешённые расширения

| Категория | Расширения |
|---|---|
| Изображения | `.png` `.jpg` `.jpeg` `.webp` `.gif` `.bmp` `.tiff` `.tif` `.svg` |
| Видео | `.mp4` `.webm` `.mov` `.avi` `.mkv` `.m4v` |

Архивы (`.zip` / `.7z` / `.rar`) **не поддерживаются** путём перетягивания. Поместите
файлы архивов непосредственно в корень сканирования и запустите обычное сканирование.

## Ограничения

- Общий размер запроса ограничен на `MAX_CONTENT_LENGTH` (по умолчанию **100 MB**)
- Имена файлов содержащие обход пути (`..`) отклоняются
- Перетягивание целой директории в настоящее время не поддерживается (только отдельные файлы)

## HTTP API

### `POST /api/dnd-upload`

Принимает загрузки файлов multipart, сохраняет их в Drop Inbox и регистрирует
их в библиотеке.

Ответ:

```json
{
  "ok": true,
  "total": 3,
  "success": 2,
  "results": [
    { "ok": true, "status": "added", "file_id": 12345, "path": "...", "filename": "a.png" },
    { "ok": true, "status": "skipped", "path": "...", "filename": "b.png" },
    { "ok": false, "code": "unsupported_type", "error": "...", "filename": "c.xyz" }
  ]
}
```

### `GET /api/dnd-inbox`

Возвращает в настоящее время разрешённый Drop Inbox для оверлея UI для отображения.

```json
{ "ok": true, "inbox": "D:/Pictures/AI/inbox", "explicit": true }
```

### `POST /api/files/register-path`

Регистрирует файл уже на диске по пути (без загрузки). Путь должен находиться внутри
`scan_roots`. Используется инструментом MCP `register_file`.

```json
{ "path": "D:/Pictures/AI/inbox/a.png" }
```

## MCP Инструменты

| Инструмент | Описание |
|---|---|
| `register_file(path)` | Зарегистрировать файл по абсолютному пути в библиотеку |
| `drop_inbox_info()` | Возвращает в настоящее время разрешённую директорию Drop Inbox |
