# Fleet-управление (Fleet Admin)

Функция Fleet Admin в LAN Cowork позволяет централизованно управлять несколькими узлами yu-ai-manager в сети.

## Обзор

- **Сбор информации о машинах**: Централизованный сбор данных CPU / RAM / GPU / диск / версия / время работы каждого узла
- **Удалённый просмотр логов**: Live-стриминг логов любого пира через SSE из UI центрального узла
- **Распространение обновлений версий**: Отправка команды `git pull --ff-only` + graceful restart указанным пирам с центрального узла

## Предварительные требования

- Extension LAN Cowork должен быть включён (`extensions["builtin-lan-cowork"].enabled = true`)
- Сопряжение (pairing) между пирами должно быть завершено
- Репозиторий должен быть клонирован через git (для функции обновлений)
- В виртуальном окружении Python должен быть установлен `psutil>=5.9`

## Настройка

### Конфигурация главного узла (chief)

Добавьте в `config.json`:

```json
{
  "extensions": {
    "builtin-lan-cowork": {
      "fleet": {
        "chief": true,
        "allow_remote_update": true,
        "allow_update_from": [
          "<peer_id сопряжённого пира>"
        ],
        "allow_log_stream_from": [
          "<peer_id сопряжённого пира>"
        ],
        "allowed_branches": [
          "main"
        ],
        "timings": {
          "chief_observation_sec": 25,
          "peers_poll_interval_sec": 30,
          "heartbeat_timeout_sec": 60,
          "update_job_timeout_sec": 600,
          "postcheck_timeout_sec": 180
        }
      }
    }
  }
}
```

### Конфигурация рядового узла

```json
{
  "extensions": {
    "builtin-lan-cowork": {
      "fleet": {
        "chief": false,
        "allow_remote_update": true,
        "allow_update_from": [
          "<peer_id главного узла>"
        ],
        "allow_log_stream_from": [
          "<peer_id главного узла>"
        ],
        "allowed_branches": [
          "main"
        ]
      }
    }
  }
}
```

## Доступ к Fleet UI

Откройте в браузере на главном узле `/ext/lan_cowork/fleet/ui`.

На рядовых узлах этот URL возвращает 404.

## Функции вкладок

### Вкладка «Обзор»

- Карточки всех узлов (с полосами использования CPU / RAM / GPU / Disk)
- Отображение состояния: онлайн / офлайн / ошибка получения данных
- Бейдж `[CHIEF]` на главном узле
- Автообновление каждые 30 секунд + кнопка ручного обновления
- Предупредительный баннер при обнаружении нескольких chief-узлов

### Вкладка «Логи»

- Live-отображение логов любого пира через SSE (наподобие `tail -f`)
- Фильтр уровня (DEBUG / INFO / WARNING / ERROR)
- Строка поиска (клиентская фильтрация)
- Включение/отключение автопрокрутки
- Пауза / возобновление

### Вкладка «Обновления»

- Таблица сравнения версий / git-коммитов / веток
- Кнопка «Pull & Restart» для отдельного узла
- Массовое обновление нескольких узлов (dispatch)
- Отображение прогресса (precheck → fetching → pulling → restarting → online)
- Главный узел исключается из массовых обновлений (только индивидуальная кнопка)

## Безопасность

### Двухуровневая авторизация

1. **Сопряжение (идентификация)**: Bearer-токен для определения «кто»
2. **Allowlist (права доступа)**: Явная авторизация для каждой операции

Сопряжённый = полные права — это не так.

### Пример конфигурации allowlist

```json
"allow_update_from": [
  "abc123def456",
  {"peer_id": "def456abc789"}
]
```

- Поддерживаются как строки, так и формат `{peer_id: ...}`
- peer_id самого устройства добавляется автоматически (настраивать не нужно)

## Автоматическое понижение chief

Если в одной сети запущено несколько узлов с `chief = true`, более поздно запущенный автоматически понижается (после `chief_observation_sec` секунд наблюдения).

После понижения для возврата статуса chief требуется перезапуск с изменённой конфигурацией (автоматического повышения нет).

## Ограничения git-обновлений

- Используется только `git pull --ff-only` (без merge/rebase)
- При невозможности fast-forward обновление немедленно переходит в статус `failed` (рабочее дерево не изменяется)
- Обновление отклоняется, если рабочее дерево «грязное»

## Устранение неполадок

| Симптом | Причина | Решение |
|---------|---------|---------|
| `/fleet/ui` возвращает 404 | `chief = true` не установлен | Проверить config.json и перезапустить |
| `/fleet/info` возвращает 500 | psutil не установлен | `uv pip install psutil>=5.9` |
| Ошибка `git_not_available` | git отсутствует или PATH неверный | Проверить установку git |
| Таймаут `postcheck_online` после обновления | Перезапуск занял более 3 минут | Увеличить `postcheck_timeout_sec` |
| Баннер обнаружения нескольких chief не исчезает | Остался старый chief-процесс | Перезапустить старый chief |

## Справочник API

### Общие для всех узлов

| Эндпоинт | Описание |
|----------|----------|
| `GET /ext/lan_cowork/fleet/info` | Информация о машине (требуется Bearer-аутентификация) |
| `GET /ext/lan_cowork/fleet/logs/stream` | SSE-стриминг логов узла (авторизация через allowlist) |
| `POST /ext/lan_cowork/fleet/update` | git pull + перезапуск (авторизация через allowlist) |
| `GET /ext/lan_cowork/fleet/update/status` | Статус задания обновления |

### Только для главного узла

| Эндпоинт | Описание |
|----------|----------|
| `GET /ext/lan_cowork/fleet/peers` | Агрегированные данные всех пиров |
| `GET /ext/lan_cowork/fleet/logs/stream?peer_id=X` | SSE-ретрансляция логов указанного пира |
| `POST /ext/lan_cowork/fleet/update/dispatch` | Массовое обновление нескольких пиров |
| `GET /ext/lan_cowork/fleet/update/dispatch/status` | Прогресс dispatch-задания |
| `GET /ext/lan_cowork/fleet/ui` | Fleet UI |
