# Руководство по обучению LoRA

Полное руководство по обучению LoRA на естественном языке с yu_ai_manager + MCP + kohya_ss

---

## Введение

Это руководство объясняет рабочий процесс создания LoRA с использованием интеграции MCP сервера yu_ai_manager с kohya_ss, полностью управляемый инструкциями на естественном языке.

Основная часть традиционного времени создания LoRA затрачивалась на ручую подготовку набора данных: выбор изображений, просмотр и фильтрацию тегов, форматирование файлов подписей, организация структуры папок — все это делалось вручную.

Интеграция MCP yu_ai_manager меняет это. Одна инструкция типа "Создай LoRA для X, исключив теги Y и Z" запускает весь конвейер: от автоматического тегирования и генерации набора данных до запуска обучения kohya_ss.

---

## Общий рабочий процесс

Создание LoRA состоит из пяти этапов:

| Фаза | Задача | Ответственность |
|-------|------|---------------|
| 1. Подготовка источников | Сбор и размещение обучающих изображений | Человек / ИИ-агент |
| 2. Тегирование | Автоматическое тегирование через WD-Tagger | MCP (автоматически) |
| 3. Создание набора данных | Создание проекта, установка исключённых тегов, экспорт | MCP (автоматически) |
| 4. Обучение | Вызов kohya_ss и запуск обучения | MCP (автоматически) |
| 5. Проверка | Тестирование LoRA в SD и проверка результатов | Человек |

Участие человека ограничивается решением того, что обучать, и проверкой конечного результата.

## Предварительные требования

### Требуемое программное обеспечение

- yu_ai_manager — включает функциональность MCP сервера
- Claude Desktop или Claude Code — MCP клиент
- kohya_ss — должен включать sd-scripts
- Stable Diffusion WebUI (A1111 / ComfyUI / Forge) — для проверки результатов

### Требования к GPU

| VRAM GPU | Поддерживаемые модели | Необходимые настройки |
|---------|-----------------|-------------------|
| 8GB | Только SD 1.5 (практически) | `--gradient_checkpointing` обязателен |
| 12GB | SDXL работает (с ограничениями) | `--gradient_checkpointing` + `--cache_latents_to_disk` |
| 16GB | SDXL удобно | Работает с настройками по умолчанию |
| 24GB+ | SDXL и FLUX поддерживаются | Почти без ограничений |

> **Примечание**: обучение SDXL LoRA на RTX 3060 12GB возможно, но требуется gradient_checkpointing, поэтому 24,000 шагов занимают примерно 10 часов. Предполагается, что RTX 5060 Ti 16GB сократит это до 3–5 часов.

### Структура каталога kohya_ss

kohya_ss часто отделяет каталог верхнего уровня от фактического каталога скрипта:

```
O:\webui\kohya_ss\              ← Каталог верхнего уровня для установки как kohya_path
O:\webui\kohya_ss\venv\         ← Виртуальное окружение Python (определяется автоматически)
O:\webui\kohya_ss\sd-scripts\   ← Каталог содержащий скрипты обучения
```

> ⚠️ **Примечание**: Укажите каталог верхнего уровня как `kohya_path` — yu_ai_manager автоматически обнаруживает подпапку `sd-scripts` и venv. Не указывайте напрямую на sd-scripts.

## Настройки yu_ai_manager

### Конфигурация расширения

Введите следующее на вкладке параметров LoRA Dataset Manager:

| Параметр | Описание | Пример |
|---------|-------------|---------|
| `kohya_path` | Верхний каталог kohya_ss | `O:\webui\kohya_ss` |
| `output_base_dir` | Базовый каталог для вывода набора данных | `C:\lora_datasets` |
| `checkpoint_dir` | Каталог содержащий базовые контрольные точки модели | `O:\webui\models\Stable-diffusion` |
| `default_base_model` | Тип модели по умолчанию | `sdxl` |

### Параметры WD-Tagger

Использование VLM (llava и т.д.) вместе с WD-Tagger не рекомендуется для наборов данных LoRA. VLM генерируют большое количество теги в свободной форме, которые ухудшают качество подписей.

```
engine_type: "onnx"  ← Используйте только ONNX
```

> ⚠️ **Примечание**: установка `engine_type` на `"both"` вызывает создание составных тегов, полученных из VLM (например, `wooden_bear_and_fish_sculpture`). Они не функционируют как подписи kohya_ss и будут препятствовать обучению.

## Шаги создания LoRA через MCP

### Шаг 1: Подготовка исходных изображений

Разместите обучающие изображения в корневом каталоге сканирования yu_ai_manager и отсканируйте их.

- Добавьте папку обучения в параметрах Scan Root yu_ai_manager
- По завершении сканирования целевые изображения регистрируются в БД
- Минимум 20–30 изображений; рекомендуется 50–200 изображений

> **Примечание**: качество изображения является одним из самых больших детерминантов результата обучения. Выбирайте изображения с разрешением 512 пикселей или выше, где объект четко виден.

### Шаг 2: Тегирование с помощью WD-Tagger

Запустите пакетное тегирование из MCP:

```python
# Получить список целевых ID файлов и пакетно их разметить
wd_tagger_batch(file_ids=[...], expected_count=N)
wait_for_batch(job_id="wd_tagger")
```

Если существующие теги присутствуют, удалите их сначала:

```python
wd_tagger_delete_tags_batch(file_ids=[...], expected_count=N)
```

### Шаг 3: Создание проекта

```python
create_lora_project(
    name="carved_bear",
    concept="carved_bear",   # Используется как имя папки kohya_ss
    base_model="sdxl",
    repeat=20
)
```

### Шаг 4: Конфигурирование файлов и тегов

Установите ID файлов на проект и просмотрите сводку по тегам:

```python
update_lora_project(project_id=N, file_ids=[...])
get_lora_project_tags(project_id=N)
```

Просмотрите сводку по тегам, чтобы решить, какие теги исключить.

#### Стратегия исключения тегов

Это ядро решения того, что будет изучать LoRA.

**Теги для сохранения**: Особенности, уникальные для концепции, которую вы хотите обучить (форма, стиль, характерные элементы)

**Теги для исключения**: Универсальные теги, которые базовая модель уже знает (`no_humans`, `realistic`, `animal`, `solo`, теги, связанные с фоном, и т.д.)

Пример — LoRA из вырезанного деревянного медведя:

- Сохранить: `bear`, `fish`, `statue`, `sculpture`, `standing`, `full_body`, `open_mouth`
- Исключить: `no_humans`, `animal_focus`, `animal`, `realistic`, `simple_background`, `solo`, `indoors`, `shadow`...

> ⚠️ **Примечание**: Если не изолировать концепцию, обучение рассеется. Если вы хотите сохранить `bear` или `wood`, имейте в виду, что WD-Tagger ONNX может не надежно присвоить эти. Проверьте фактический вывод через предпросмотр подписей.

```python
update_lora_project(
    project_id=N,
    tag_exclude=["no_humans", "animal_focus", "animal", "realistic", ...]
)
```

### Шаг 5: Предпросмотр подписей

```python
preview_lora_caption(project_id=N, file_id=<any_file_id>)
```

Примерный выход:

```
"fish, full_body, open_mouth, standing"
```

Убедитесь, что вывод представляет собой чистый, простой список тегов без шума VLM. Если многие подписи пусты, пересмотрите исключённые теги.

### Область действия модели

Каждый проект имеет параметр `model_scope`, который управляет тем, какая модель WD-Tagger используется для подписей, предпросмотра и экспорта.

- `active` (по умолчанию для новых проектов): Используйте теги только из активной модели WD. Если активная модель не установлена, она переходит на все модели.
- `all` (по умолчанию для существующих проектов): Смешивание тегов из всех моделей.
- `<model_id>` (например, `wd-eva02-large-tagger-v3`): Используйте теги только из явно выбранной модели.

Для файлов, разметанных несколькими моделями, `active` обычно достаточно. Когда вам нужна явная модель для сравнения или валидации, используйте тот же model_id, показанный в раскрывающемся списке профиля WD-Tagger на странице "Tools".

### Шаг 6: Экспорт набора данных

```python
export_lora_dataset(project_id=N)
```

Структура выходной папки:

```
{output_base_dir}/{project_name}/{repeat}_{concept}/
    image001.jpeg
    image001.txt   ← подпись
    image002.jpeg
    image002.txt
```

### Шаг 7: Запуск обучения

Сначала просмотрите команду с пробным запуском:

```python
preview_lora_train_command(
    project_id=N,
    checkpoint="full\path\to\checkpoint.safetensors"
)
```

Если все выглядит правильно, начните обучение:

```python
start_lora_training(
    project_id=N,
    checkpoint="full\path\to\checkpoint.safetensors",
    extra_args=["--gradient_checkpointing", "--xformers", "--cache_latents_to_disk"]
)
```

Проверьте ход выполнения:

```python
get_lora_train_status(project_id=N, tail=20)
```

## Параметры обучения по умолчанию

| Параметр | По умолчанию | Описание |
|-----------|---------|-------------|
| `network_dim` | 32 | Ранг LoRA. Выше = более выразительный, но больший размер файла |
| `network_alpha` | 16 | Обычно установлен на половину dim |
| `learning_rate` | 1e-4 | Скорость обучения |
| `max_train_epochs` | 10 | Количество эпох |
| `save_every_n_epochs` | 2 | Интервал для промежуточных сохранений |
| `mixed_precision` | fp16 | Точность. bf16 может сэкономить VRAM в некоторых случаях |
| `resolution` | 1024,1024 (SDXL) | Разрешение обучения. SD1.5 использует 512,512 |

> **Примечание**: Их можно изменить на вкладке "Параметры" или через `set_extension_config`. Дополнительные аргументы можно передать через `extra_args` в `start_lora_training`.

---

## Рекомендуемые параметры по GPU

| VRAM GPU | Рекомендуемые extra_args |
|---------|----------------------|
| 8GB | `--gradient_checkpointing --xformers --cache_latents_to_disk --optimizer_type=AdamW8bit` |
| 12GB | `--gradient_checkpointing --xformers --cache_latents_to_disk` |
| 16GB | (работает с настройками по умолчанию) |
| 24GB+ | (работает с настройками по умолчанию; batch_size можно увеличить) |

> ⚠️ **Примечание**: Использование gradient_checkpointing на GPU 12GB означает ~10–12 часов для 24,000 шагов SDXL. 16GB+ убирает это ограничение и значительно ускоряет обучение.

## Инструкции по повтору и эпохе

**Всего шагов обучения = количество изображений × повторение × количество эпох**

| Сложность концепции | Рекомендуемые шаги | Пример (50 изображений) |
|-------------------|------------------|---------------------|
| Простой объект или стиль | 1,000–3,000 | repeat=10, epoch=5 |
| Персонаж или скульптурный объект | 3,000–8,000 | repeat=20, epoch=5 |
| Сложный стиль или человек | 5,000–15,000 | repeat=20, epoch=10 |

> **Примечание**: обучение с 120 изображениями × 20 повторений × 10 эпох = 24,000 шагов дает хорошие результаты качества. Однако 5–6 эпох могут дать эквивалентные результаты, поэтому рекомендуется сначала попробовать меньше эпох.

## Устранение неисправностей

### ModuleNotFoundError: No module named 'torch'

**Причина**: yu_ai_manager пытается запустить скрипты kohya_ss из собственного venv.

**Исправление**: Установите `kohya_path` в каталог верхнего уровня (родитель sd-scripts). yu_ai_manager автоматически обнаруживает `kohya_path/venv/Scripts/python.exe`.

---

### AssertionError: resolution is required

**Причина**: `--resolution` не был указан.

**Исправление**: Последняя версия yu_ai_manager добавляет это автоматически (SDXL: 1024,1024; SD1.5: 512,512).

---

### AssertionError: network for Text Encoder cannot be trained with caching

**Причина**: `--cache_text_encoder_outputs` и `--network_train_unet_only` не связаны по парам.

**Исправление**: Последняя версия yu_ai_manager автоматически добавляет `--network_train_unet_only` для SDXL.

---

### torch.OutOfMemoryError: CUDA out of memory

**Причина**: Недостаточно VRAM.

**Исправление**: Добавьте следующее в `extra_args`:

```python
extra_args=["--gradient_checkpointing", "--xformers", "--cache_latents_to_disk"]
```

---

### Теги шума VLM в подписях

**Причина**: `engine_type` установлен на `"both"`, что вызывает создание VLM (llava и т.д.) тегов в свободной форме.

**Исправление**: Измените на `engine_type="onnx"` в параметрах WD-Tagger, удалите все теги и переразметьте.

```python
wd_tagger_save_config({"engine_type": "onnx"})
wd_tagger_delete_tags_batch(file_ids=[...], expected_count=N)
wd_tagger_batch(file_ids=[...], expected_count=N)
```

---

### checkpoint must be inside checkpoint_dir (403 error)

**Причина**: Путь контрольной точки указывает за пределы `checkpoint_dir`.

**Исправление**: Убедитесь, что `checkpoint_dir` в параметрах расширения указывает на правильный каталог.

---

### output_base_dir not configured (400 error)

**Причина**: `output_base_dir` в параметрах расширения не установлен или не сохранен.

**Исправление**: Переохраняйте на вкладке параметров пользовательского интерфейса или установите через `set_extension_config` из MCP.

## Генерирование подсказок

### Базовая структура подсказки

```
{concept_token}, {feature_tags}, <lora:{lora_name}:{strength}>
```

Пример для LoRA из вырезанного деревянного медведя:

```
carved_bear, wooden sculpture, bear statue, wood texture, brown,
full_body, standing, open_mouth, fish, simple_background,
<lora:carved_bear:0.7>
```

Негативная подсказка:

```
blurry, lowres, bad anatomy, worst quality, flat color, monochrome
```

### Корректировка силы LoRA

| Сила | Характеристики |
|----------|----------------|
| 0.5–0.6 | Базовая модель имеет большее влияние; цвет и стиль ближе к базовой модели |
| 0.7–0.8 | Рекомендуемый диапазон; хороший баланс между особенностями LoRA и базовой моделью |
| 0.9–1.0 | LoRA имеет сильное влияние; форма проявляется, но цвета склоняются к белому/кремовому |

> **Примечание**: Если цвета вымываются в белое, снизьте силу или добавьте `brown wood, warm tone` в подсказку, чтобы направить цвет.

## Будущие расширения

### Автоматизация сбора источников

В настоящее время исходные изображения должны подготавливаться вручную. Используя агента браузера, как Claude в Chrome, вы можете автоматизировать это инструкциями типа "собрать изображения X из сети и положить их в папку."

Использование собственных сгенерированных yu_ai_manager изображений в качестве источника обучения также эффективно — изображения, сгенерированные SD/ComfyUI/NAI, можно переработать прямо в качестве материала для обучения LoRA.

### Поток производства массовой LoRA

С MCP + Claude Desktop полная автоматизация достижима:

1. Собрать исходные изображения из сети (Claude в Chrome)
2. Сканировать и разметить в yu_ai_manager (MCP)
3. Создать проект, настроить исключённые теги, экспортировать (MCP)
4. Запустить обучение kohya_ss (MCP)
5. Дать инструкции перед сном → LoRA готова к утру

### Выбор базовой модели

Модели на основе Illustrious, такие как waiSHUFFLENOOB, оптимизированы для создания в стиле аниме. Обучение на фотографических объектах (например, вырезанные деревянные медведи) имеет тенденцию производить цветовые переливы белого/кремового.

Для фотореалистичного качества используйте базовую модель типа realisticPhoto. LoRA должна использоваться с той же моделью, на которой она была обучена.

---

## Резюме

Рабочий процесс yu_ai_manager + MCP + kohya_ss значительно сокращает время и усилия, необходимые для создания LoRA.

- Полное обучение эпохи из исходных изображений завершается только инструкциями MCP
- Весь рабочий процесс работает с инструкциями на естественном языке
- Сгенерированные изображения четко выражают форму изученного объекта

Единственным оставшимся ручным шагом является сбор исходных изображений, который можно автоматизировать, комбинируя с агентами браузера, что делает полную сквозную автоматизацию достижимой.
