# Сканирование

## Регистрация папок для сканирования

Добавить папки для сканирования на вкладке Settings > Scan.

- Изменение порядка перетаскиванием
- Включение/отключение через чекбокс
- Поддержка нескольких папок

## Запуск сканирования

- Автоматический запуск после добавления папки
- Ручной запуск со страницы Tools или через MCP `trigger_scan`
- Прогресс сканирования передаётся в реальном времени по SSE

## Автосканирование (Watcher)

При включённом Extension Auto Scan Watcher автоматически обнаруживаются изменения файлов в зарегистрированных папках.

## Удалённые файловые системы

При сканировании удалённых путей (WSL / NAS / SMB) настройте таймаут на вкладке Settings > Remote FS.

## Сканирование больших библиотек

Особенности сканирования сотен тысяч и более файлов:

- **Поиск доступен во время сканирования**: API поиска использует соединение с БД только для чтения и не блокируется записью при сканировании
- **Автоуправление WAL**: При сканировании каждые 2000 файлов автоматически выполняется checkpoint WAL, предотвращая разрастание файла WAL
- **Событие scan.db_busy**: SSE-событие при начале/завершении сканирования — фронтенд может отображать состояние занятости

## Процесс сканирования в отдельном потоке

С v3.27.0 сканирование выполняется в отдельном от web_ui.py процессе.
Благодаря этому **сканирование не прерывается при перезапуске web_ui**.

### Принцип работы

- При запуске сканирования из WebUI запускается фоновый процесс-воркер
- Воркер записывает файл прогресса (JSON) и PID-файл в `/tmp/yu-scan/`
- WebUI опрашивает этот файл прогресса и транслирует данные на фронтенд по SSE
- При перезапуске WebUI автоматически обнаруживает работающий воркер и восстанавливает отображение прогресса

### Управление через CLI

Воркер можно управлять и через CLI. Используется даже при остановленном WebUI.

```bash
# Проверить состояние
python -m core.scan.scan_worker status

# Остановить работающее сканирование (graceful shutdown — сохраняет позицию в DB)
python -m core.scan.scan_worker stop

# Запустить сканирование напрямую из CLI
python -m core.scan.scan_worker start --db ./tags.db --root /path/to/images
```

### Защитные механизмы

- **Мониторинг родительского процесса**: Воркер, запущенный из WebUI, проверяет его существование каждые 60 секунд. При аварийном завершении WebUI воркер автоматически сохраняет состояние прерывания и останавливается
- **Поддержка SIGTERM**: Команда `stop` или `kill` с SIGTERM завершает текущую обработку, делает коммит в DB и сохраняет позицию прерывания
- **Защита от дублирования**: Одновременно не может работать несколько воркеров

## Ошибки сканирования

При ошибках во время сканирования можно проверить через MCP `get_scan_errors`.
