# Планировщик задач

## Обзор

Планировщик задач — функция для автоматического выполнения регулярных задач:
обслуживания базы данных, опроса внешних сервисов и т.д.
Фоновый планировщик на базе APScheduler управляет заданиями с триггерами cron / interval.

Со страницы планировщика (`/scheduler`) WebUI можно просматривать, добавлять, удалять,
приостанавливать задания и запускать их немедленно.

## Настройка

Планировщик включён по умолчанию. Управляется параметром `scheduler.enabled` в `config.json`:

```json
{
  "scheduler": {
    "enabled": true,
    "jobs": {
      "db_vacuum": { "enabled": true, "trigger": "cron", "day_of_week": "sun", "hour": 3, "minute": 0 },
      "db_integrity_check": { "enabled": true, "trigger": "cron", "hour": 4, "minute": 0 },
      "thumbnail_cleanup": { "enabled": true, "trigger": "cron", "hour": 5, "minute": 0 }
    }
  }
}
```

## Список встроенных заданий

### Обслуживание базы данных

| ID задания | Описание | Рекомендуемая частота |
|-----------|---------|----------------------|
| `db_vacuum` | Выполнить SQLite VACUUM для освобождения неиспользуемого пространства | 1 раз в неделю |
| `db_integrity_check` | Проверка целостности через `PRAGMA integrity_check` | Ежедневно |
| `db_backup` | Создать резервную копию базы данных | Ежедневно |

### Управление кэшем и индексами

| ID задания | Описание | Рекомендуемая частота |
|-----------|---------|----------------------|
| `thumbnail_cleanup` | Удалить просроченные файлы кэша миниатюр | Ежедневно |
| `prune_unused_tags` | Удалить осиротевшие теги без привязки к файлам | 1 раз в неделю — в месяц |
| `refresh_monthly_stats` | Обновить предвычисленный кэш месячной статистики | Ежедневно |
| `rebuild_groups_index` | Перестроить кэш индекса групп папок/архивов | 1 раз в неделю |

### Интеграция с внешними сервисами

| ID задания | Описание | Рекомендуемая частота |
|-----------|---------|----------------------|
| `github_issue_poll` | Опрос GitHub API и добавление новых Issue в локальную очередь | 5 мин – 1 час |
| `bsky_notification_poll` | Опрос Bluesky API и получение новых уведомлений | 5 мин – 1 час |

## Настройка триггеров

### Триггер cron

Выполнение в конкретное время, день недели или дату.

| Параметр | Пример | Описание |
|----------|--------|---------|
| `hour` | `3`, `*/6`, `1,13` | Часы (0–23). `*` — каждый час |
| `minute` | `0`, `30`, `0,30` | Минуты (0–59). `*` — каждую минуту |
| `day` | `1`, `15`, `1,15` | Дни (1–31). `*` — каждый день |
| `day_of_week` | `sun`, `mon-fri`, `0-4` | День недели. `*` — каждый день |

**Пример**: Выполнять 1-го и 15-го числа каждого месяца в 2:30

```json
{ "trigger": "cron", "day": "1,15", "hour": 2, "minute": 30 }
```

### Триггер interval

Повторение с фиксированным интервалом.

**Пример**: Каждые 30 минут

```json
{ "trigger": "interval", "minutes": 30 }
```

## Использование WebUI

### Немедленный запуск задания

Запустить задание вне расписания — кнопка **«Запустить сейчас»**.

### Пауза / возобновление

Временно остановить или возобновить периодическое выполнение задания.

### История выполнений

В нижней части страницы отображается история последних выполнений (максимум 50).
При завершении задания обновляется в реальном времени по SSE.

## MCP-инструменты

| Инструмент | Описание |
|-----------|---------|
| `get_scheduler_status` | Получить состояние планировщика |
| `list_scheduled_jobs` | Получить список зарегистрированных заданий |
| `trigger_scheduled_job` | Запустить задание немедленно |
| `pause_scheduled_job` | Приостановить задание |
| `resume_scheduled_job` | Возобновить задание |
| `get_scheduler_history` | Получить историю выполнений |

## Советы

- **Задания опроса внешних сервисов** (`github_issue_poll`, `bsky_notification_poll`) лучше использовать с триггером interval
- **`db_vacuum`** захватывает блокировку записи — рекомендуется ночное время с минимальным трафиком
