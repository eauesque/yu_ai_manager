# Руководство по изоляции на уровне ОС

Функция для ограничения влияния Extension (расширений) на систему с помощью механизмов безопасности ОС.

## 1. Что такое изоляция ОС

При установке приложения на смартфон появляется сообщение «Это приложение запрашивает доступ к камере».
Изоляция ОС работает по той же концепции.

На основе разрешений, задекларированных Extension (чтение/запись файлов, сетевые соединения,
запуск внешних программ и т.д.), **ядро ОС физически блокирует недозволенные операции**.
Никакие техники в Python-коде не позволят обойти ограничения уровня ядра.

> **Примечание**: Эта функция предназначена главным образом для безопасного использования сторонних Extension.
> Builtin-Extension (`builtin-*`) обрабатываются как доверенные (L0) и работают без ограничений.

---

## 2. Поддерживаемые платформы

| ОС | Метод изоляции | Зрелость |
|----|---------------|---------|
| **Linux** | AppArmor (Mandatory Access Control) | Рекомендуется, готово к производственному использованию |
| **macOS** | sandbox-exec (Seatbelt) | Экспериментально (Apple объявила устаревшим) |
| **Windows** | Restricted Token + Job Object | Базовые ограничения ресурсов |

Наиболее полная реализация — AppArmor на Linux.

## 3. Настройка Linux (AppArmor)

### 3.2 Автоматическая настройка

```bash
sudo bash scripts/setup-apparmor.sh
```

Скрипт выполняет:
1. Проверку и установку AppArmor-пакетов
2. Добавление `lsm=apparmor` в параметры ядра
3. Установку правил sudoers для беспарольного запуска `apparmor_parser`
4. Включение AppArmor-сервиса в systemd

### 3.3 Перезагрузка

```bash
sudo reboot
```

### 3.4 Проверка работы

```bash
cat /sys/module/apparmor/parameters/enabled
# → "Y" если включён

sudo aa-status
```

### 3.5 Включение в config.json

```json
{
  "os_isolation": {
    "enabled": true,
    "linux": {
      "apparmor": true
    }
  }
}
```

## 5. Соответствие разрешений Extension и правил AppArmor

| Разрешение Extension | Управление AppArmor |
|---------------------|---------------------|
| `db:read` | Только чтение директории `data/` |
| `db:write` | Чтение и запись директории `data/` |
| `fs:read:scan_roots` | Чтение настроенных корневых директорий |
| `network:local` | TCP/Unix socket (UDP запрещён) |
| `network:internet` | TCP/UDP/Unix socket разрешены |
| `subprocess` | Разрешено выполнение из `/usr/bin/`, `/bin/` и т.д. |
| Без сетевых разрешений | TCP/UDP явно запрещены, только Unix socket для IPC |

## 6. Устранение неполадок

### AppArmor не включается

```bash
cat /sys/module/apparmor/parameters/enabled
# → "N"
```

**Решение**:
- Raspberry Pi OS: Убедиться в наличии `lsm=apparmor` в `/boot/firmware/cmdline.txt` и перезагрузиться
- Окружение GRUB: Проверить `GRUB_CMDLINE_LINUX="... lsm=apparmor"` и выполнить `sudo update-grub && sudo reboot`

## 7. Примечания по безопасности

Изоляция ОС — часть многоуровневой защиты. YU AI Manager обеспечивает безопасность через:

1. **Статический анализ** — AST-анализ кода Extension при установке, обнаружение опасных import
2. **Гейткипер разрешений** — Контроль доступа через прокси с проверкой разрешений
3. **Изоляция ОС** — Принудительные ограничения файлов/сети/процессов на уровне ядра

Для сторонних Extension рекомендуется использовать с включённой изоляцией ОС в Linux-окружении.
