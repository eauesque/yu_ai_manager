# Руководство по настройке распределённого вывода

> Целевая версия: v4.67.0 и более поздние

## Что такое распределённый вывод?

Функция, при которой несколько узлов yu_ai_manager сотрудничают для **параллелизации и распределения** обработки вывода, такой как теггирование, CLIP, YOLO и распознавание речи. Вы можете распределять сканирование больших файлов на несколько машин или делегировать теггирование на Pi5 с Hailo NPU.

```
┌──────────────┐   Пакет изображений ┌──────────────┐
│    Local     │ ──────────────────► │  Pi5 (Hailo) │  tagger × 200 изображений
│   (Сканир.)  │ ──────────────────► │ GPU-машина   │  tagger × 300 изображений
│              │ ──────────────────► │    Local     │  tagger × 100 изображений
└──────────────┘   Работа            └──────────────┘
                  Краска
```

---

## Предварительные условия

На каждом узле должны быть выполнены следующие условия:

1. yu_ai_manager запущен
2. **Расширение LAN Cowork включено** (`"extensions": {"builtin-lan-cowork": {"enabled": true}}`)
3. Узлы **спарены друг с другом** ([Руководство аутентификации узла](../lan-cowork/peer-auth.md))
4. Модули вывода, которые будут использоваться, настроены на каждом узле (ONNX / Hailo / Whisper и т.д.)

---

## Этапы настройки

### Этап 1: Включите LAN Cowork на каждом узле

В `config.json` на всех узлах:

```json
{
  "extensions": {
    "builtin-lan-cowork": {
      "enabled": true
    }
  }
}
```

После перезагрузки узлы будут автоматически обнаруживать друг друга через mDNS.

### Этап 2: Завершите сопряжение

Выполните сопряжение между всеми парами узлов (двусторонний).
Детали: [Аутентификация PIN узла и сопряжение токена](../lan-cowork/peer-auth.md)

### Этап 3: Проверьте матрицу распределённого вывода

Откройте `/mesh-inference` на любом узле.

Спаренные узлы отображаются как строки, типы вывода — как столбцы:

| Узел | tagger | clip | yolo | whisper |
|---|---|---|---|---|
| Local | ☑ Включено | ☑ Включено | ☑ Включено | ☑ Включено |
| pi5-hailo | ☑ Включено | ☑ Включено | — Недоступно | — Недоступно |
| gpu-win | ☑ Включено | ☑ Включено | ☑ Включено | ☑ Включено |

- **☑ Включено**: Использовать этот узел для вывода
- **☐ Отключено**: Пропустить (можно переключать вручную)
- **—**: Этот узел не имеет целевого модуля вывода (не может быть использован)

### Этап 4: Проверьте работу

Запустите пакет теггирования и убедитесь в журналах, что используется несколько узлов:

```
[mesh-inference] dispatching tagger: 600 items to 3 peers
[mesh-inference] pi5-hailo: processed 200, errors 0
[mesh-inference] gpu-win:   processed 300, errors 0
[mesh-inference] local:     processed 100, errors 0
```

## Требования по типу вывода

| Тип | Требуемый модуль | Описание |
|---|---|---|
| `tagger` | ONNX (WD14 и т.д.) или Hailo NPU | Теггирование в стиле Danbooru для изображений |
| `clip` | ONNX CLIP или Hailo | Семантические векторы встраивания для изображений (для семантического поиска) |
| `yolo` | ONNX YOLO | Обнаружение объектов на изображениях |
| `whisper` | faster-whisper или удаленный | Преобразование речи в текст для аудио/видео |

Узлы без настроенного модуля будут показывать «—» для этого типа и не будут маршрутизироваться для этого типа.

## Примеры проектирования ролей

### Пример 1: Выделение Pi5 + Hailo NPU только для теггирования

Выделите Pi5 исключительно для теггирования, чтобы снизить нагрузку на другие узлы.

Конфигурация матрицы:
- Pi5: tagger ☑, другие ☐
- Local: clip ☑, yolo ☑, whisper ☑, tagger ☐ (делегировать на Pi5)

### Пример 2: Быстрое массовое сканирование

Включите tagger как на GPU-машине, так и на локальной машине, автоматически распределяя файлы через краинговый труд. Ручное разделение не требуется.

### Пример 3: Режим только локальный (временный)

Нажмите кнопку "Только локальный режим" в `/mesh-inference`, чтобы отключить все удаленные узлы сразу. Полезно при отключении сети.

## Устранение неполадок

### Узел не отображается в матрице

1. Проверьте, что узел распознан с помощью `/api/lan/peers`
2. Убедитесь, что сопряжение завершено ([peer-auth.md](../lan-cowork/peer-auth.md))
3. Проверьте, что LAN Cowork включен на удаленном узле

### Маршрутизация на определённый узел не работает

- Убедитесь, что целевой тип для этого узла показывает ☑ в матрице
- Проверьте, что ответ от `/api/lan/peers` показывает `status: "online"` для этого узла
- Убедитесь, что сердцебиение удаленного узла принимается (поищите `heartbeat` в журналах)

### Всё обрабатывается локально

Если все удаленные узлы отключены или недоступны, происходит автоматический локальный откат.
Это нормальная работа (не ошибка).

### Ошибка `no_enabled_peers`

Этот тип отключен на всех узлах.
Включите хотя бы 1 узел для этого типа в матрице.
