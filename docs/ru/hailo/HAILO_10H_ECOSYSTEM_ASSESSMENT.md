# Оценка экосистемы Hailo-10H

**Дата создания**: 2026-03-19
**Объект**: Hailo-10H (AI HAT 2 для Raspberry Pi 5)
**HailoRT**: v5.2.0
**DFC**: v5.2.0
**Цель**: Документировать опыт разработки с Hailo-10H в этом проекте и упорядочить реалистичные ограничения и перспективы

---

## Общая оценка

**Железо отличное. Программная экосистема критически недоразвита.**

Hailo-10H — это NPU с производительностью 40 TOPS, аппаратный потенциал вполне достаточный. Однако закрытость и незрелость цепочки инструментов делают **практически невозможным** свободное использование собственных моделей разработчиками.

В данном проекте Hailo-10H использовался многосторонне: CLIP семантический поиск, YOLO обнаружение объектов, LLM/VLM чат, распознавание речи Whisper, распределённый тэггер-сервер. Однако всё, что стабильно работает, использует **исключительно предварительно скомпилированные HEF из официального Model Zoo Hailo**, и не было ни одного случая, когда удалось бы самостоятельно конвертировать ONNX в HEF.

## Статус реализации в проекте

### Работающие функции (все используют официальные HEF)

| Функция | API | Источник HEF |
|---------|-----|-------------|
| CLIP энкодер изображений | `VDevice.create_infer_model()` | Hailo Model Zoo (S3) |
| YOLO обнаружение объектов | `VDevice.create_infer_model()` | Hailo Model Zoo (S3) |
| LLM чат | `hailo_platform.genai.LLM` | Hailo GenAI Model Zoo |
| VLM инференс изображений+текста | `hailo_platform.genai.VLM` | Hailo GenAI Model Zoo |
| Whisper распознавание речи | `hailo_platform.genai.Speech2Text` | Hailo GenAI Model Zoo |

### Нереализованные функции (сбой конвертации HEF)

| Функция | Что пробовали | Результат |
|---------|---------------|----------|
| WD-Tagger (SwinV2) | Конвертация ONNX → HEF | DFC не может обработать LayerNormalization |
| WD-Tagger (ViT) | Конвертация ONNX → HEF | То же |
| WD-Tagger (ConvNeXt) | Конвертация ONNX → HEF | DFC не может обработать Transpose |

### Особенности реализации

Все функции в этом проекте реализованы путём **прямого вызова** Python API из `hailo_platform` wheel. hailo-ollama и hailo-apps не использовались.

Следующее построено самостоятельно до официальных релизов от Hailo:

- **Менеджер устройства с эксклюзивным управлением VDevice** — автоматическое переключение между CLIP/YOLO/LLM/VLM/S2T на одном VDevice. В hailo-apps нет механизма совместного использования устройств
- **Мультибэкендный фолбэк** — прозрачное автопереключение Hailo → CoreML → ONNX Runtime
- **Пайплайн деквантования uint8** — восстановление float32 из scale/zero_point `quant_info`
- **Архитектура распределённого LAN-инференса** — параллельное тегирование с work-stealing на нескольких машинах

Вся эта разработка велась **в условиях практически полного отсутствия API-документации**. Спецификации входа/выхода InferModel API, требования к размерам буферов, способы получения параметров квантования — всё это было выяснено из сообщений об ошибках и анализа исходного кода.

## Проблемы с Hailo Dataflow Compiler (DFC)

### Что такое DFC

Компилятор для конвертации ONNX / TensorFlow моделей в HEF (Hailo Executable Format) для Hailo-10H.
Работает на x86_64 Linux и конвертирует модели по следующему пайплайну:

```
model.onnx → HAR (float32) → оптимизация → квантование (INT8) → компиляция → model.hef
```

### Реальность

**DFC нормально конвертирует только те архитектуры, которые Hailo предварительно проверила для собственного Model Zoo.**

Попытки конвертации в этом проекте (2026-03-06, DFC v5.2.0):

| Модель | Размер | Ошибка | Этап |
|--------|--------|--------|------|
| wd-swinv2-tagger-v3 | 446 МБ | `IndexError` в `_convert_axes_to_nhwc` | До оптимизации |
| wd-vit-tagger-v3 | 362 МБ | То же | До оптимизации |
| wd-convnext-tagger-v3 | 377 МБ | `UnsupportedShuffleLayerError` | До оптимизации |

Все три модели **провалились ещё на уровне парсера** до достижения этапа оптимизации. Подготовленные 500 изображений для калибровки так и не были использованы.

### Первопричина

ONNX-парсер DFC не может обработать следующие операторы:

- `LayerNormalization` (преобразование осей в многомерных тензорах)
- `Transpose` (паттерны конвертации channels-last/first)

Это базовые строительные блоки Transformer-архитектур (SwinV2, ViT, ConvNeXt и т.д.),
которые используются в большинстве современных моделей с 2022 года.

### Реальный охват DFC

| Архитектура | Поддержка DFC | Основание |
|-------------|---------------|----------|
| ResNet, MobileNet и другие CNN | ✓ Поддерживается | Множество в Model Zoo |
| YOLO v5/v8/v11 | ✓ Поддерживается | HEF есть в Model Zoo |
| CLIP ViT (версия Hailo) | ✓ Поддерживается | HEF есть в Model Zoo (конвертирован Hailo) |
| SwinTransformer V2 | ✗ Не поддерживается | Сбой конвертации LayerNorm |
| Vision Transformer (общий) | ✗ Не поддерживается | Сбой конвертации LayerNorm |
| ConvNeXt | ✗ Не поддерживается | Сбой конвертации Transpose |

> **Примечание**: CLIP ViT есть в Model Zoo скорее всего потому, что Hailo применяла специальную внутреннюю обработку (ручное преобразование графа или кастомный парсер). Обычные пользователи при конвертации того же ViT через DFC потерпят неудачу.

## Проблемы с форматом HEF

- **Спецификация формата закрыта** — Hailo не публикует документацию по формату
- **DFC — единственный способ генерации** — создать HEF сторонними инструментами невозможно
- **Обратная разработка нереалистична** — требуются знания набора инструкций NPU и архитектуры потока данных

То есть модели, которые DFC не может конвертировать, **не запустить на Hailo-10H никаким способом**. Альтернативы не существует.

## Оценка цепочки инструментов разработки

### hailo_platform (Python SDK)

| Элемент | Оценка |
|---------|--------|
| InferModel API | Работает, но документация крайне недостаточна |
| GenAI API (LLM/VLM/S2T) | Относительно удобен. Много недокументированного поведения |
| Дистрибуция Python wheel | Нет на PyPI. Wheel для aarch64 требует сборки из исходников |
| Сообщения об ошибках | Минимальны. Сложно определить причину несоответствия размеров буфера |
| Управление VDevice | Только эксклюзивный доступ. Одновременное использование нескольких моделей невозможно |

### Недокументированное поведение, выявленное при разработке

1. **InferModel API — правильный вариант** — старый VStreams API (`InferVStreams`, `ConfigureParams.create_from_hef`) возвращает `HAILO_NOT_IMPLEMENTED` на Hailo-10H
2. **Выход квантован в uint8** — выделение буфера как float32 даёт `buffer size mismatch`. Нужно выделить как uint8, затем деквантовать
3. **`input()`/`output()` — свойства**, не методы (несоответствие с остальными API Hailo)
4. **Получение `quant_info`** — доступно через `infer_model.output().quant_info` для получения scale/zero_point, но документация об этом отсутствует
5. **Взаимное исключение с hailo-ollama** — во время использования VDevice нужно останавливать hailo-ollama. Из сообщений об ошибках причина неочевидна

## Сравнение с конкурентами

### Ryzen AI (XDNA) NPU

| Элемент | Hailo-10H | Ryzen AI (XDNA) |
|---------|-----------|-----------------|
| Производительность | 40 TOPS | 16–50 TOPS (зависит от поколения) |
| Использование собственных моделей | Конвертация через DFC обязательна, обычно не удаётся | **ONNX Runtime поддерживает напрямую** |
| DX разработчика | Проприетарная цепочка, недостаток документации | Установка одной командой `pip install onnxruntime-directml` |
| Экосистема | Закрытая, зависимость от Model Zoo | ONNX / DirectML / совместная разработка с Microsoft |
| Распространённость | Pi + AI HAT, USB-донгл (планируется) | **Встроен в миллионы ноутбуков** |

Интеграция с Ryzen AI сводится к:

```python
import onnxruntime as ort
session = ort.InferenceSession("model.onnx", providers=["DmlExecutionProvider"])
```

На Hailo-10H то же самое невозможно. Execution Provider для ONNX Runtime отсутствует.

### NVIDIA CUDA

| Элемент | Hailo-10H | NVIDIA CUDA |
|---------|-----------|-------------|
| Использование собственных моделей | Через DFC, обычно не удаётся вне Model Zoo | ONNX / PyTorch / TensorFlow → работают напрямую |
| Цепочка инструментов | Незрелая, полузакрытая | Зрелая, открытая, обширная документация |
| Сообщество разработчиков | Очень малое | Крупнейшее в мире |
| Ценовой диапазон | Дёшево (~$70) | Дорого ($200–$2000+) |

Единственное преимущество Hailo — **цена и энергопотребление**.

## Связь с hailo-apps (октябрь 2025)

### Обзор hailo-apps

Официальный набор приложений от Hailo, выпущенный в октябре 2025 года. Включает 20+ образцов:

- GenAI: voice_assistant, vlm_chat, agent_tools_example, whisper
- Pipeline: обнаружение объектов, оценка позы, распознавание лиц, CLIP-классификация, OCR
- Standalone: демонстрационные Python/C++ для изучения HailoRT

### Сравнение с данным проектом

| Элемент | hailo-apps | Данный проект |
|---------|-----------|--------------|
| Поддержка VLM | Приложение vlm_chat | Прямая реализация `hailo_platform.genai.VLM` |
| CLIP | Приложение clip | Интегрировано как система семантического поиска |
| LLM | simple_llm_chat | Интегрировано как GenAI Extension |
| Whisper | simple_whisper_chat | Интегрировано как Speech-to-Text Extension |
| Управление устройством | Нет (рассчитано на одно приложение) | **Эксклюзивный менеджер устройства (автопереключение CLIP/YOLO/LLM/VLM/S2T)** |
| Фолбэк бэкенда | Нет | **Автопереключение Hailo → CoreML → ONNX** |

Данный проект реализовал функциональность, равную или превосходящую официальные приложения hailo-apps, самостоятельно через низкоуровневые API `hailo_platform` wheel — ещё до публикации hailo-apps.

## Перспективы

### Краткосрочные (реалистичные)

- **ONNX Runtime + LAN-распределение — единственное практичное решение** — эксплуатация через ONNX-бэкенд распределённого тэггер-сервера
- Использование Hailo-10H ограничено задачами с официальными HEF (YOLO, CLIP, LLM, Whisper)
- Запуск кастомных моделей на NPU отменяется

### Среднесрочные (оптимистичные)

- Выпуск USB-донгла с Hailo-10H от ASUS и т.д. → рост числа пользователей
- Рост пользовательской базы может создать давление на Hailo для улучшения инструментов
- В будущих версиях DFC возможно появление поддержки Transformer-архитектур

### Долгосрочные (структурные проблемы)

- Без предоставления Hailo ONNX Runtime EP экосистема разработчиков проиграет Ryzen AI (XDNA)
- Даже при распространении железа через USB-донглы, без свободы ПО останется «быстрым ключом с YOLO»
- Потенциал 40 TOPS останется закованным в десятках моделей Model Zoo

---

## Итог

Hailo-10H имеет отличную аппаратную производительность в 40 TOPS, но из-за закрытости и незрелости программной экосистемы разработчикам **практически невозможно** свободно использовать собственные модели.

В данном проекте был построен программный комплекс, превосходящий официальные приложения Hailo (hailo-apps), путём самостоятельного исследования недокументированных API. Однако даже так выполнить инференс кастомных моделей (WD-Tagger) на NPU не удалось из-за ограничений DFC.

**«Инструментов слишком мало, чтобы разработка была реально возможна»** — таков честный итог нескольких месяцев разработки с Hailo-10H.
