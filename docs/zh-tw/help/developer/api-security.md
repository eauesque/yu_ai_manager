# API 安全指南

每當添加或更改 API 端點時，請使用此文件。

## 首要決策

每個端點必須提前分類為以下之一：

- `public`
- `session/user`
- `admin`
- `localhost-only`

如果不確定，請選擇 `admin`。

## 核心規則

1. 不要假設 `GET` 是安全的。
2. `read-only API keys` 僅用於簡單讀取。
3. 內部路徑、庫存、歷史記錄、內容、日誌和分析結果是 `admin`。
4. 本地主機檢查必須使用感知代理的輔助程式。
5. 配置端點需要允許清單和嚴格驗證。
6. 秘密必須加密並通過共用輔助程式進行編輯。

## 對於唯讀金鑰不安全

- 內部路徑
- 文件/成員 ID 庫存
- 提示、註釋、轉錄、聊天日誌
- OCR / 分析結果
- 隊列、歷史記錄、審計、批准、排程程式、掃描錯誤狀態
- 擴充功能 / 設定檔 / 備份 / webhook / 秘密後端狀態
- 使用儲存的第三方認證取得的結果

## 本地主機檢查

不要直接使用：

```
request.remote_addr == "127.0.0.1"
```

改用現有輔助程式：

- `get_client_ip()`
- `is_local_request()`
- `is_loopback_request()`

## 配置端點規則

必需：

- 金鑰允許清單
- 嚴格的類型驗證
- 範圍 / 列舉 / URL 驗證
- 讀取時的秘密編輯
- 秘密的加密儲存

禁止：

- 盲 `config.update(...)`
- 請求布林的 `bool(value)`
- 繞過秘密處理的通用合併

## 秘密

- 永遠不要傳回目前秘密值
- 永遠不要在清單端點中包含權杖/標頭/秘密 blob
- 永遠不要用遮罩佔位符覆蓋現有秘密
- 始終使用專用儲存或共用輔助程式

## 來自 API 的出站請求

不要從 `GET` 端點進行上游探針或發現提取。

如果不可避免：

- 需要 `admin`
- 保持逾時短
- 阻止本地主機 / 專用 IP / 中繼資料目標

## 最少測試

對於敏感端點，添加：

1. `read-only key -> 403`
2. `admin key -> 200`
3. `invalid input -> 400`
4. 秘密編輯檢查
5. 感知代理的本地主機迴歸測試（如相關）

## 審查清單

- 這個 `GET` 真的對公開/唯讀存取安全嗎?
- 它是否暴露了路徑、庫存、提示、轉錄、歷史記錄或原始中繼資料?
- 它是否洩露了秘密?
- 它是否使用了感知代理的輔助程式?
- 它是否避免了隱式布林強制?
- 它是否避免了盲配置合併?
- 它是否避免了無意的出站請求?
- 它是否包含了管理員範圍的迴歸測試?

預設原則：從狹窄開始，然後僅在需要時故意開啟。
