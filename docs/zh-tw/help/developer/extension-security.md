# Extension 安全模型

本軟體的特色是「任何人都能用 AI 建立 Extension」。
同時，內建了保護你的系統免受惡意 Extension 侵害的機制。

本頁說明這些機制的運作方式。
即使你不是技術人員也能看懂。

---

## 基本原則

Extension 在一個**受保護的世界**中執行。

在這個受保護的世界裡，Extension 可以相當自由地運作。
新增頁面、顯示資料、處理影像——這些都是 Extension 的工作。

但是，受保護的世界**之外**的東西——系統核心（core）、其他 Extension、你電腦上的所有檔案——它碰不到。
這不是「規則禁止」，而是**在結構上根本碰不到**。

---

## 權限機制

Extension 做任何事都需要**權限**。

權限的設計與智慧型手機的 App 權限模型完全相同。

- 相機 App 要求使用相機——理所當然
- 相機 App 要求存取你的通訊錄——很不正常

Extension 也一樣。如果一個加浮水印的 Extension 要求網路存取權限，你就該起疑。

### 核准流程

1. 安裝 Extension（或讓 AI 幫你建立）
2. YU AI Manager 自動掃描程式碼，檢查它想做什麼
3. 顯示 Extension 所要求的權限清單
4. **在你核准之前，Extension 不會執行**

認真閱讀核准畫面上顯示的資訊。
特別注意那些以紅色標示的權限。

### 核准權限之後

Extension 在你核准的權限範圍內運作。
未核准的權限，Extension 再怎麼努力也用不了。
不是「嘗試使用時被拒絕」，而是「根本看不見」。

---

## 三重獨立監控

你的 Extension 受到三個獨立機制的監控。
這三者互相獨立——即使其中一個被騙過，另外兩個仍然正常運作。

### 1. 程式碼掃描

自動分析 Extension 的程式碼，偵測危險模式。
執行外部程式、直接操作資料庫、動態執行程式碼——這些都會被立即偵測到。

### 2. 權限控制

Extension 呼叫 API 時，系統會確認它是否持有有效的「許可證」（Capability Token）。
許可證只有在你核准權限時才會核發。
Extension 自己無法偽造許可證。

### 3. 稽核紀錄

Extension 的所有操作都會被記錄。
這些紀錄保存在 Extension 自身無法竄改的獨立位置。

一旦偵測到異常——例如，Extension 嘗試執行未宣告的動作——系統會自動發送通知，必要時撤銷 Extension 的許可證。

---

## 用 AI 建立 Extension 的情況

從 Claude Desktop 建立 Extension 時，建立出來的 Extension 會自動以**最嚴格的限制等級**註冊。

這就像不會在新員工第一天就把金庫鑰匙交給他一樣。
先以有限的權限執行，確認沒有問題後，再依需求追加權限。

### AI 建立的 Extension 能做什麼

**無需核准即可使用：**
- 讀取和顯示資料
- 在 UI 中新增頁面
- 新增設定畫面

**需要核准：**
- 與外部服務通訊
- 寫入資料庫
- 讀取檔案

**無論如何都不可能做到：**
- 讀取或修改系統核心（core）
- 讀取或修改其他 Extension
- 執行外部程式
- 偽造許可證

---

## 定期檢查

Extension 不是核准一次就結束了。

如果程式碼被修改，且修改量超過一定閾值，就會要求**重新核准**。
這是為了防止透過逐步小幅修改，在不知不覺中把 Extension 變成完全不同的東西。

此外，系統會定期自動重新檢查程式碼。
即使核准時沒有問題，新的檢查規則也可能發現問題。

---

## 你該做的事

1. **好好讀權限核准畫面** — 搞清楚它在要求什麼再核准
2. **拒絕不合理的權限要求** — 影像處理不需要網路存取
3. **不要忽略通知** — 偵測到異常時去確認
4. **不要安裝來路不明的 Extension** — 這是常識

反過來說，只要做到這些就安全了。
