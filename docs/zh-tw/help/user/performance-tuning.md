# 效能調校指南

本指南適用於管理 10 萬個以上檔案的環境，協助您順暢使用 YU AI Manager。
預設設定已包含許多自動最佳化，但根據環境調整可進一步改善效能。

---

## 1. 建議硬體規格

| 項目 | 最低需求 | 建議（10 萬檔案以上） |
|------|---------|------------------------|
| CPU | 2 核心 | 4 核心以上（縮圖生成會並行處理） |
| RAM | 4 GB | 8 GB 以上 |
| 儲存裝置 | HDD | **強烈建議使用 SSD** — 直接影響資料庫的回應速度 |
| 網路 | — | 透過 LAN 使用時建議 1 Gbps 以上 |

**特別重要**：資料庫檔案 (`data/tags.db`) 務必放在 SSD 上。
圖片檔案本體放在 HDD 上沒問題，但 DB 若在 HDD 上，搜尋和瀏覽速度會顯著變慢。

---

## 2. 初次掃描的最佳化

### 分割掃描根目錄

一次掃描大量檔案會花費較長時間。
建議在 Settings > Scan Roots 中將掃描根目錄分成多個進行註冊，分階段掃描。

- 先掃描最常使用的資料夾
- 其餘資料夾加入掃描佇列（會自動依序處理）
- 重複註冊同一資料夾會自動偵測並跳過

### 掃描中仍可瀏覽

掃描中搜尋和縮圖顯示仍可正常使用。
內部使用唯讀資料庫連線，掃描的寫入處理不會阻擋瀏覽。

### 掃描完成後的自動最佳化

掃描完成時會自動更新資料庫統計資訊（ANALYZE）。
藉此最佳化搜尋查詢的執行計畫，後續搜尋將更加快速。
無需任何特別操作。

---

## 3. 瀏覽速度的改善

### Service Worker 快取

瀏覽器的 Service Worker 會自動快取以下內容：

| 種類 | 快取上限 | 效果 |
|------|-------------|------|
| 縮圖 | 5,000 件 | 第二次以後的格狀檢視顯示即時 |
| 預覽（1200px） | 200 件 | 加速彈窗顯示 |
| 原尺寸圖片 | 50 件 | 最近瀏覽過的圖片再顯示即時 |

Service Worker 由瀏覽器自動管理，無需特別設定。
若要清除快取，可在瀏覽器開發者工具 > Application > Storage 中操作。

### 啟用虛擬捲動

顯示數千筆搜尋結果時，啟用虛擬捲動可大幅改善繪製效能。

**啟用步驟**：Settings > Appearance > 將「Virtual Scroll」設為 ON

虛擬捲動僅將畫面可見範圍的卡片繪製到 DOM，大幅降低記憶體用量和繪製負擔。
數萬件規模的圖庫強烈建議啟用。

### WebP 縮圖

縮圖以 WebP 格式生成（比 JPEG 小 30-40%）。
藉此減少傳輸量，特別在 LAN 存取時效果顯著。
無需設定，自動套用。

## 4. 搜尋效能

### 索引的效果

資料庫已自動建立針對主要搜尋模式最佳化的索引。
日期排序、標籤篩選、路徑搜尋等均可高速運作。

**參考指標**：
- 無篩選搜尋：28 萬件規模下回應在 50ms 以內
- 含標籤篩選搜尋：100ms 以內
- 路徑搜尋（FTS5）：50ms 以內

### FTS5 全文搜尋 vs LIKE 搜尋

路徑搜尋自動使用 FTS5 (Full-Text Search) 索引。
相較於傳統的 LIKE 搜尋 (`%keyword%`)，速度快 20-100 倍。

若無法使用 FTS5（從舊版 DB 升級時等），會自動退回至 LIKE 搜尋。
執行一次掃描即可建立 FTS5 索引。

**中文搜尋注意事項**：包含中文字元的搜尋內部可能會使用 LIKE 退回。
這是 SQLite FTS5 分詞器的限制，屬於正常行為。

## 5. 影片播放的最佳化

### Faststart 快取

為加速 MP4/MOV 檔案的影片播放，會自動套用 faststart 處理。
已 faststart 處理的影片可立即開始串流播放。

| 項目 | 值 |
|------|-----|
| 快取位置 | `cache/faststart/` |
| 容量上限 | 4 GB（以 LRU 自動管理） |
| 單檔上限 | 500 MB |
| 對象 | MP4, MOV（WebM 不需要，因此跳過） |

**體感改善參考**：

| 檔案大小 | 無 faststart | 有 faststart |
|--------------|---------------|---------------|
| 5-50 MB | 等待 2-10 秒 | 約 200ms 開始播放 |
| 50-200 MB | 等待 10-60 秒 | 約 500ms 開始播放 |
| 200-500 MB | 等待數分鐘 | 約 1 秒開始播放 |

### 確認 FFmpeg

faststart 處理需要 FFmpeg。若未安裝，影片將在完全下載後才開始播放。

```bash
ffmpeg -version
```

若 PATH 中找不到 FFmpeg，請從[官方網站](https://ffmpeg.org/download.html)安裝。

## 6. 記憶體用量管理

### SQLite mmap

大規模資料庫（10 萬檔案以上）會自動將 SQLite 的 mmap（記憶體映射 I/O）設為 1 GB。
藉此讓讀取查詢利用 OS 的頁面快取來加速。

**RAM 4 GB 以下的環境**：mmap 可能會造成記憶體壓力。
此時請監控系統可用記憶體，若頻繁發生交換（swap），請關閉其他應用程式。

### 瀏覽器分頁管理

YU AI Manager 透過 SSE (Server-Sent Events) 與各分頁進行即時通訊。

- 每個 IP 最多 10 個同時 SSE 連線
- 關閉不需要的分頁可釋放連線資源
- 開啟大量分頁也會增加瀏覽器的記憶體用量

**建議**：同時開啟的分頁控制在 3-4 個以內。

## 7. 疑難排解 — 感覺「很慢」時的檢查清單

### 基本確認

- [ ] **是否使用 SSD**：若 `data/tags.db` 在 HDD 上，所有操作都會變慢
- [ ] **是否已安裝 FFmpeg**：影片播放加速的必要條件
- [ ] **瀏覽器分頁數**：確認是否開啟了 5 個以上

### 瀏覽速度慢

- [ ] **啟用虛擬捲動**：Settings > Appearance > Virtual Scroll
- [ ] **不要清除瀏覽器快取**：Service Worker 的快取正在發揮作用
- [ ] **確認是否正在掃描**：掃描中可正常使用，但初次縮圖生成需要時間

### 搜尋速度慢

- [ ] **完成掃描**：掃描完成時會執行 ANALYZE，搜尋將被最佳化
- [ ] **搜尋結果超過 10 萬件**：請新增篩選條件（標籤、日期、路徑等）以縮小範圍

### 影片播放慢

- [ ] **確認 FFmpeg 是否存在**：以 `ffmpeg -version` 確認
- [ ] **faststart 快取容量**：確認 `cache/faststart/` 資料夾是否超過 4 GB（自動管理但可確認）
- [ ] **檔案大小**：超過 500 MB 的影片不在 faststart 快取範圍內。以 Range 傳送播放，但首次會稍慢

### 伺服器整體負擔重

- [ ] **同時存取數**：SSE 連線是否超過每 IP 10 個
- [ ] **上傳中**：是否正在傳送接近 100 MB 上傳上限的檔案
- [ ] **Settings > Logs 分頁**：確認伺服器日誌中的錯誤或警告

## 8. 效能指標參考

正常最佳化環境下的回應時間參考。

| 操作 | 28 萬檔案規模 | 10 萬檔案規模 |
|------|-----------------|-----------------|
| 格狀檢視顯示（首次） | 200-500ms | 100-300ms |
| 格狀檢視顯示（有快取） | 50ms 以下 | 50ms 以下 |
| 標籤搜尋 | 100ms 以下 | 50ms 以下 |
| 路徑搜尋（FTS5） | 50ms 以下 | 30ms 以下 |
| 縮圖（快取命中） | 5ms 以下 | 5ms 以下 |
| 影片播放開始（faststart 已處理） | 200ms | 200ms |

若大幅超過這些數值，請確認上述檢查清單。

## 高速模式（Rust 伺服器）

在支援的環境中，啟動會自動切換到 Rust 伺服器（`yu-server`）。

可在設定 ->「伺服器」->「高速模式」中選擇**取得方式**：

- **下載發佈的二進位檔**（預設）-- 不編譯
- **在本機編譯** -- 不下載
- **先下載，失敗則編譯**

編譯需要 8GB 以上可用磁碟空間，並會大量佔用 CPU 與記憶體。**在記憶體較小的裝置（如 Raspberry Pi）上可能耗盡置換空間並導致整個系統當機。** 編譯期間所有功能仍可使用。在 Windows 上編譯還需要 Visual Studio 的建置工具（連結器）。

進度顯示在同一畫面上（已用時間、cargo 的最新一行、成功或失敗，以及是否中途停止）。原始日誌位於 `bin/fast-mode-build.log`。

當高速模式因本副本自身的狀態被拒絕時（web 套件過舊、存在隨附清單之外的擴充等），重新取得二進位檔也無法解決，因此既不下載也不編譯。原因同樣顯示在該畫面上。
