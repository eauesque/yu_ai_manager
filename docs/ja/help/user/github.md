# GitHub Integration

## 概要

GitHub Integration は、YU AI Manager から GitHub のリポジトリ・Issue・Pull Request・Discussion・リリースを一元管理できる拡張機能です。複数の GitHub アカウントに対応し、トークンは暗号化して安全に保存されます。ダッシュボードで通知やリポジトリ統計を素早く確認でき、AI によるIssue トリアージ機能も備えています。

## セットアップ

### GitHub Personal Access Token (PAT) の取得

1. GitHub にログインし、**Settings > Developer settings > Personal access tokens > Tokens (classic)** を開く
2. **Generate new token (classic)** をクリック
3. トークン名を入力し、有効期限を設定する
4. スコープで **`repo`** にチェックを入れる（リポジトリへのフルアクセスに必要）
5. **Generate token** をクリックし、表示されたトークンをコピーする

> **注意**: トークンはこの画面でしか表示されません。必ずコピーしてから閉じてください。

### アカウントの追加

1. Extensions ランチャーから **GitHub** カードをクリック、または `/ext/github` に直接アクセス
2. **Settings** タブを開く
3. **アカウント追加** をクリック
4. 以下の情報を入力する:
   - **ラベル**: アカウントの表示名（例: 「個人」「仕事用」）
   - **トークン**: 上記で取得した PAT
   - **リポジトリ**: 監視するリポジトリを `owner/repo` 形式で入力（複数可）
5. 保存後、ドロップダウンからアカウントを選択する

## 機能

### ダッシュボード

アカウントを選択すると、ダッシュボードが自動的に読み込まれます。

- **通知**: 未読の GitHub 通知を一覧表示
- **リポジトリ統計**: スター数・フォーク数・オープン Issue 数をカード形式で表示
- **サマリーカード**: 監視対象リポジトリの概況を一目で把握

### Issues

- リポジトリ・状態（open/closed）でフィルタリング
- Issue の詳細表示（本文・コメント・ラベル）
- 新規 Issue の作成
- **トリアージ機能**: AI が Issue を自動分類
  - `valid_bug` — 有効なバグ報告
  - `needs_info` — 追加情報が必要
  - `skip` — 対応不要
- **Issue キュー**: GitHub の新規 Issue を自動ポーリングしてローカルにキューイング。MCP クライアント（Claude Desktop）接続時に未読分をまとめて通知。

### Pull Requests

- PR の一覧表示とフィルタリング
- 差分統計の表示（追加行数・削除行数・変更ファイル数）
- 詳細ビューでファイルごとの変更内容を確認

### Discussions

- GraphQL API 経由でディスカッション一覧を取得
- カテゴリバッジ・回答済みバッジの表示

### Releases

- 監視対象リポジトリの最新リリースを一覧表示
- リリースノートの確認

### Settings

- アカウントの追加・編集・削除・有効/無効切り替え
- API レート制限の残量表示
- 言語フィルター・スケジュール間隔の設定
- Issue キューのポーリング間隔・無効 Issue の自動クローズ・MCP 接続通知の設定
- Issue・PR・Discussion のトリアージプロンプトの編集（[例を見る](/help/github-triage-examples)）

### Issue キュー

Issue キューは GitHub を定期的にポーリングし、新しい Issue をローカルに保存します。

- **ポーリング**: スケジューラにより自動実行（間隔は設定可能、デフォルト 60 分）
- **通知**: MCP 接続時に、未処理の Issue を Claude Desktop にまとめて通知
- **トリアージ**: キューに入った各 Issue を有効・無効に分類可能
- **自動クローズ**: 無効と判定された Issue をテンプレートコメント付きで GitHub 上で自動クローズ
- **手動ポーリング**: Settings の「Poll Now」をクリックすると即座に取得

### トリアージプロンプト

Issue・PR・Discussion のトリアージ時に使用する AI 指示文をカスタマイズできます。

- 各タイプ（Issue・PR・Discussion）ごとに個別の編集可能なプロンプトを用意
- デフォルトプロンプトが提供されており、「デフォルトに戻す」でいつでも復元可能
- 複数言語・スタイルのテンプレートは[トリアージプロンプト例](/help/github-triage-examples)を参照
- プロンプトは config.json に保存（秘密情報を含まないため暗号化なし）

## MCP 連携

GitHub Integration には 12 の MCP ツールが用意されており、Claude Code から直接操作できます。

- Issue の一覧取得・詳細表示
- PR の一覧取得・詳細表示
- 通知の取得
- トリアージプロンプトの取得・更新
- Issue キューの管理（未処理一覧・トリアージ・却下・ポーリング）

MCP ツールを使うことで、コード編集中に IDE を離れることなく GitHub の情報を参照できます。

## ヒント

- **複数アカウント**: 個人用と仕事用など、用途ごとにアカウントを分けると管理しやすくなります
- **トークンの権限**: `repo` スコープがあれば基本機能は全て使えます。Organization のプライベートリポジトリにアクセスする場合は、Organization での SSO 認可が別途必要です
- **トリアージの活用**: Issue が多いリポジトリでは、トリアージ機能で優先度を自動分類すると効率的です
- **レート制限**: GitHub API には時間あたりのリクエスト上限があります。Settings タブで残量を確認できます
- **トークンの安全性**: トークンはサーバー側で暗号化して保存されます。平文で保存されることはありません
- **ダッシュボードの更新**: アカウントを切り替えると自動的にデータが再取得されます
