# タスクスケジューラ

## 概要

タスクスケジューラは、データベースメンテナンスや外部サービスのポーリングなどの定期タスクを自動実行する機能です。APScheduler ベースのバックグラウンドスケジューラが cron / interval トリガーでジョブを管理します。

WebUI のスケジューラページ (`/scheduler`) から、ジョブの一覧確認・追加・削除・一時停止・即時実行が可能です。

## セットアップ

スケジューラはデフォルトで有効です。`config.json` の `scheduler.enabled` で制御できます:

```json
{
  "scheduler": {
    "enabled": true,
    "jobs": {
      "db_vacuum": { "enabled": true, "trigger": "cron", "day_of_week": "sun", "hour": 3, "minute": 0 },
      "db_integrity_check": { "enabled": true, "trigger": "cron", "hour": 4, "minute": 0 },
      "thumbnail_cleanup": { "enabled": true, "trigger": "cron", "hour": 5, "minute": 0 }
    }
  }
}
```

`config.json` に記述したジョブはサーバー起動時に自動登録されます。WebUI から追加したジョブはサーバーセッション中のみ有効です（再起動で消えます）。

## ビルトインジョブ一覧

### データベースメンテナンス

| ジョブ ID | 説明 | 推奨頻度 |
|-----------|------|---------|
| `db_vacuum` | SQLite VACUUM を実行し、未使用領域を回収する | 週1回 |
| `db_integrity_check` | `PRAGMA integrity_check` でデータベースの整合性を検証する | 毎日 |
| `db_backup` | データベースのバックアップを作成する（builtin-backup extension 経由） | 毎日 |

### キャッシュ・インデックス管理

| ジョブ ID | 説明 | 推奨頻度 |
|-----------|------|---------|
| `thumbnail_cleanup` | 期限切れのサムネイルキャッシュファイルを削除する | 毎日 |
| `prune_unused_tags` | ファイルに紐付かない孤立タグレコードを削除する | 週1〜月1回 |
| `refresh_monthly_stats` | 月次統計の事前計算キャッシュを更新する | 毎日 |
| `rebuild_groups_index` | フォルダ・アーカイブのグループインデックスキャッシュを再構築する | 週1回 |

### 外部サービス連携

| ジョブ ID | 説明 | 推奨頻度 |
|-----------|------|---------|
| `github_issue_poll` | GitHub API をポーリングし、新規 Issue をローカルキューに取り込む | 5分〜1時間 |
| `bsky_notification_poll` | Bluesky API をポーリングし、新規通知を取得する | 5分〜1時間 |

## トリガー設定

### cron トリガー

特定の時刻・曜日・日付に実行します。Unix cron に類似した指定方法です。

| パラメータ | 値の例 | 説明 |
|-----------|--------|------|
| `hour` | `3`, `*/6`, `1,13` | 時 (0-23)。`*` で毎時 |
| `minute` | `0`, `30`, `0,30` | 分 (0-59)。`*` で毎分 |
| `day` | `1`, `15`, `1,15` | 日 (1-31)。`*` で毎日 |
| `day_of_week` | `sun`, `mon-fri`, `0-4` | 曜日。`*` で毎日 |

**例**: 毎月1日と15日の午前2時30分に実行

```json
{ "trigger": "cron", "day": "1,15", "hour": 2, "minute": 30 }
```

### interval トリガー

一定間隔で繰り返し実行します。

| パラメータ | 値の例 | 説明 |
|-----------|--------|------|
| `hours` | `2` | 時間間隔 |
| `minutes` | `30` | 分間隔 |

**例**: 30分おきに実行

```json
{ "trigger": "interval", "minutes": 30 }
```

## WebUI の使い方

### ジョブ一覧

スケジューラページを開くと、登録済みジョブの一覧が表示されます。各ジョブの状態（有効/一時停止）、トリガー設定、次回実行時刻を確認できます。

### ジョブの追加

1. **ジョブ追加** ボタンをクリック
2. ジョブ ID（一意の名前）を入力
3. 実行する関数をドロップダウンから選択
4. トリガー種別（cron / interval）を選択
5. スケジュールパラメータを入力（`*` でワイルドカード指定可能）
6. **追加** をクリック

### ジョブの操作

- **今すぐ実行**: ジョブをスケジュール外で即座に1回実行
- **一時停止 / 再開**: ジョブの定期実行を一時的に止める/再開する
- **削除**: ジョブを完全に削除する（config.json のジョブは次回起動時に復元されます）

### 実行履歴

ページ下部に直近の実行履歴（最大50件）が表示されます。成功/失敗のステータスと結果メッセージを確認できます。ジョブの実行完了時は SSE でリアルタイム更新されます。

## MCP ツール

MCP クライアント（Claude Desktop 等）からスケジューラを操作できます:

| ツール | 説明 |
|--------|------|
| `get_scheduler_status` | スケジューラの稼働状態を取得 |
| `list_scheduled_jobs` | 登録済みジョブ一覧を取得 |
| `trigger_scheduled_job` | ジョブを即時実行 |
| `pause_scheduled_job` | ジョブを一時停止 |
| `resume_scheduled_job` | ジョブを再開 |
| `get_scheduler_history` | 実行履歴を取得 |

## Tips

- **外部ポーリング系ジョブ**（`github_issue_poll`, `bsky_notification_poll`）は interval トリガーが適しています。cron で固定時刻に設定するとポーリング間隔が開きすぎることがあります
- **`db_vacuum`** は書き込みロックを取得するため、アクセスの少ない深夜帯に設定することを推奨します
- **`db_backup`** は builtin-backup extension のクールダウン設定を尊重します。短い interval で設定してもクールダウン期間中はスキップされます
- **実行履歴はメモリ上**に保持されます（最大100件）。サーバー再起動で履歴はクリアされます
