# LLM Router WebUI

`/llm-router` で開く管理ダッシュボード。登録済みバックエンドの状態確認・無効化/有効化が行える。

---

## 画面構成

```
┌─────────────────────────────────────┐
│  🤖 LLM Router          [Refresh All] │
├─────────┬─────────┬────────┬─────────┤
│Backends │ Enabled │ Models │ Aliases │  ← サマリーカード
├─────────┴─────────┴────────┴─────────┤
│  Backends テーブル                    │
├───────────────────────────────────────┤
│  Routing Aliases テーブル             │
└───────────────────────────────────────┘
```

### サマリーカード（4 つ）

| カード | 内容 |
|---|---|
| **Backends** | カタログに登録されているバックエンドの総数 |
| **Enabled** | 無効化（disabled）されていないバックエンドの数 |
| **Models** | 全バックエンドが公開しているモデルの合計数 |
| **Routing aliases** | 設定ファイルで定義されているエイリアスの数 |

カードの値はページ読み込み時に `/api/llm_router/status` を取得して自動描画される。

---

## バックエンド一覧テーブル

各行が 1 つの物理バックエンド（Ollama インスタンス等）に対応する。

### 列の意味

| 列 | 説明 |
|---|---|
| **Alias** | バックエンドを識別する一意の短縮名（例: `ollama-mac`, `mdns-pi5-hailo`）。ルーティング設定やエイリアス解決のキーになる |
| **Base URL** | バックエンドの OpenAI 互換エンドポイントのベース URL（例: `http://192.168.1.10:11434`） |
| **Status** | バックエンドへの疎通状態。詳細は後述 |
| **SLO** | バックエンドのリソース負荷状態（`vision_idle` / `vision_active` / `unknown`）。Hailo Vision 系バックエンドで使用 |
| **Models** | 最後のプローブで取得したモデル数。クリックで詳細リストを展開できる実装依存の場合あり |
| **Last Seen** | 最後に正常応答を確認した日時（ISO 8601）。`null` の場合は一度も成功していない |
| **Actions** | 個別操作ボタン（後述） |

### Status の読み方

| 値 | 意味 |
|---|---|
| `ready` | 直前のプローブが成功し、モデル一覧を取得済み |
| `unreachable` | 接続タイムアウトまたはエラーが発生 |
| `unknown` | まだプローブを実行していない（起動直後など） |
| `probing` | プローブ実行中（UI が Refresh 中に短時間表示されることがある） |

> **ヒント**: `unreachable` のバックエンドはルーティング対象から外れるが、カタログには残る。ネットワーク復旧後に Refresh All または個別 Refresh を実行すると `ready` に戻る。

### SLO の読み方

| 値 | 意味 |
|---|---|
| `vision_idle` | Vision タスクのアイドル状態。LLM 負荷は低い |
| `vision_active` | Vision タスクが動作中。LLM ルーターは他バックエンドを優先することがある |
| `unknown` | SLO 情報を取得できない（非 Hailo バックエンド、または取得失敗） |

## Refresh All ボタン

画面右上の **Refresh All** をクリックすると、全バックエンドに対して強制プローブを実行し、モデル一覧・ステータスを更新する。

- 実行中はボタンが無効化され、完了後に再描画される
- 内部動作: `POST /api/llm_router/refresh`（ボディなし）を呼び出し、全バックエンドの `discover_all` を実行
- 個別バックエンドの Refresh は Actions 列の Refresh ボタン（実装により存在）から実行できる場合がある

## 個別バックエンドの disable / enable

### 操作手順

1. バックエンド一覧テーブルの **Actions** 列を確認する
2. 無効化したいバックエンドの行で **Disable** ボタンをクリック
3. ボタンが **Enable** に変わり、行がグレーアウトされる
4. 再び有効化するには **Enable** をクリック

### 動作と永続化

- 操作は即座にインメモリカタログに反映される
- 同時に `data/llm_router_state.json` へアトミック書き込みされる

  ```json
  {
    "version": 1,
    "disabled_aliases": ["ollama-slow", "mdns-pi5"]
  }
  ```

- アプリを再起動しても無効化状態は保持される
- mDNS で動的発見されるバックエンドが起動前に無効化されていた場合も、発見後に自動適用される（`_pending_disabled` 機構）
- 書き込み失敗時はインメモリ状態がロールバックされ、ディスクと不整合が生じない

### disabled バックエンドの挙動

- `/v1/chat/completions` などの OpenAI 互換エンドポイントでのルーティング対象から除外される
- disabled のバックエンドに直接ルーティングしようとすると `503 Service Unavailable` が返る
- WebUI テーブルには引き続き表示される（状態の把握と再有効化のため）

## Routing Aliases テーブル

設定ファイルで定義した論理モデル名と物理モデル ID のマッピングを表示する。

| 列 | 説明 |
|---|---|
| **Alias** | クライアントが `model` パラメータで指定する論理名（例: `default-llm`, `fast-chat`） |
| **Physical Model** | 実際にリクエストを処理する物理モデル ID（形式: `バックエンドalias/モデル名`、例: `ollama-mac/qwen2.5:7b`） |

### エイリアスの役割

エイリアスを使うと、クライアントコードを変えずにバックエンドや使用モデルを切り替えられる。

- クライアントは `"model": "default-llm"` のように論理名でリクエスト
- LLM Router が `default-llm → ollama-mac/qwen2.5:7b` に解決してプロキシ
- バックエンドを別マシンに移行する場合はエイリアスの向き先を変えるだけでよい

エイリアスは設定ファイルで静的定義され、WebUI は読み取り専用で表示する。変更には設定ファイルの編集とアプリ再起動が必要。

## よくある操作

### バックエンドが unreachable のとき

1. バックエンドサービス（Ollama 等）が起動しているか確認
2. **Refresh All** または個別 Refresh を実行
3. それでも解決しない場合は `last_error` 列（または API レスポンス）でエラー内容を確認

### mDNS で自動発見されたバックエンドを恒久的に無効化したい

1. 対象バックエンドの Actions 列で **Disable** をクリック
2. `data/llm_router_state.json` に alias が保存されるため、再発見後も無効のまま維持される

### 一時的に特定バックエンドへの負荷を止めたい

**Disable** で即座に除外 → 作業完了後 **Enable** で復帰。再起動は不要。
