# 分散推論 セットアップガイド

> 対象バージョン: v4.67.0 以降

## 分散推論とは

複数の yu_ai_manager ノードが協調して、タグ付け・CLIP・YOLO・音声認識などの  
推論処理を**並列分散**する機能です。大量ファイルのスキャンを複数マシンで分担したり、  
Hailo NPU を搭載した Pi5 にタグ付けを任せたりできます。

```
┌──────────────┐   画像バッチ    ┌──────────────┐
│   ローカル   │ ──────────────► │  Pi5 (Hailo) │  tagger × 200枚
│   (スキャン) │ ──────────────► │  GPU マシン  │  tagger × 300枚
│              │ ──────────────► │   ローカル   │  tagger × 100枚
└──────────────┘   ワーク        └──────────────┘
                   スティーリング
```

---

## 前提条件

各ノードで以下が満たされていること:

1. yu_ai_manager が起動していること
2. **LAN Cowork 拡張が有効**（`"extensions": {"builtin-lan-cowork": {"enabled": true}}`）
3. ノード同士が**ペアリング済み**（[ピア認証ガイド](../lan-cowork/peer-auth.md)）
4. 推論に使うエンジンが各ノードでセットアップ済み（ONNX / Hailo / Whisper 等）

---

## セットアップ手順

### ステップ 1: 各ノードで LAN Cowork を有効化

全ノードの `config.json`:

```json
{
  "extensions": {
    "builtin-lan-cowork": {
      "enabled": true
    }
  }
}
```

再起動後、mDNS でノードが相互発見されます。

### ステップ 2: ペアリングを完了させる

すべてのノードペアでペアリングを実施します（双方向）。  
詳細: [ピア間 PIN 認証・トークンペアリング](../lan-cowork/peer-auth.md)

### ステップ 3: 分散推論マトリクスを確認

任意のノードで `/mesh-inference` を開きます。

ペアリング済みのノードが行に、推論タイプが列に表示されます:

| ノード | tagger | clip | yolo | whisper |
|---|---|---|---|---|
| ローカル | ☑ 有効 | ☑ 有効 | ☑ 有効 | ☑ 有効 |
| pi5-hailo | ☑ 有効 | ☑ 有効 | — 未搭載 | — 未搭載 |
| gpu-win | ☑ 有効 | ☑ 有効 | ☑ 有効 | ☑ 有効 |

- **☑ 有効**: そのノードを推論に使用
- **☐ 無効**: スキップ（手動で切替可）
- **—**: そのノードが対象推論エンジンを持たない（操作不可）

### ステップ 4: 動作確認

タグ付けバッチを実行して、ログに複数ノードの使用が表示されることを確認します。

```
[mesh-inference] dispatching tagger: 600 items to 3 peers
[mesh-inference] pi5-hailo: processed 200, errors 0
[mesh-inference] gpu-win:   processed 300, errors 0
[mesh-inference] local:     processed 100, errors 0
```

---

## 推論タイプ別の要件

| タイプ | 必要なエンジン | 説明 |
|---|---|---|
| `tagger` | ONNX (WD14 等) または Hailo NPU | 画像への Danbooru スタイルタグ付け |
| `clip` | ONNX CLIP または Hailo | 画像の意味的埋め込みベクトル（セマンティック検索用）|
| `yolo` | ONNX YOLO | 画像内の物体検出 |
| `whisper` | faster-whisper またはリモート | 音声・動画の文字起こし |

エンジンが未設定のノードはそのタイプに「—」が表示され、ルーティング対象外になります。

## ロールの設計例

### 例 1: Pi5 + Hailo NPU をタグ専用に

Pi5 を tagger 専用に割り当て、他ノードの負荷を下げます。

マトリクス設定:
- Pi5: tagger ☑、その他 ☐
- ローカル: clip ☑、yolo ☑、whisper ☑、tagger ☐（Pi5 に任せる）

### 例 2: 高速一括スキャン

GPU マシン + ローカルマシンの両方で tagger を有効にして、  
ファイルをワークスティーリングで自動分担。手動分割は不要です。

### 例 3: ローカルのみモード（一時的）

`/mesh-inference` の「ローカルのみモード」ボタンで  
全リモートピアを一括無効化。ネットワーク切断時などに有効です。

## よくあるトラブル

### ピアがマトリクスに表示されない

1. `/api/lan/peers` でピアが認識されているか確認
2. ペアリングが完了しているか確認（[peer-auth.md](../lan-cowork/peer-auth.md)）
3. 相手ノードで LAN Cowork が有効になっているか確認

### 特定ノードへのルーティングが走らない

- マトリクスでそのノードの対象タイプが ☑ になっているか確認
- `/api/lan/peers` のレスポンスで `status: "online"` になっているか確認
- 相手ノードのハートビートが届いているか（ログで `heartbeat` を検索）

### 全部ローカルで処理される

リモートピアが全てオフラインまたは無効な場合、自動的にローカルフォールバックになります。  
これは正常動作です（エラーにはなりません）。

### `no_enabled_peers` エラー

全ノードでそのタイプが無効になっています。  
マトリクスで少なくとも 1 ノードを有効にしてください。
